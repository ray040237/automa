Agent 聊天区 Markdown · 引库落地（marked 词法 + 自渲染）

问题（用户提出）：聊天区正文本应把模型的 markdown 展示得"更完美"， 现在是自己手搓的解析器，是不是该换成现成的库？ 本稿前半是实测缺口与两条路的真实成本；第六节起是 最终决策与落地结果（走的是"库做词法、渲染自己出"的混合路线）。

所有"实测"数字都来自本机对 src/agent/markdown.js 的真跑，不是估计。

一、现状

  • 渲染器：src/agent/markdown.js，355 行，2026-10 之前写成。 文件头自述原因是「本机装不上 npm 依赖，仓库里也没有 markdown 库可复用」。
  • 复核（本次）：node_modules 里 marked / markdown-it / remark / micromark / DOMPurify / sanitize-html / highlight.js / prismjs 一个都没有， 也不在任何依赖的传递树里。也就是说"引库"必须先解决装依赖。
  • 宿主是浏览器扩展（MV3 语义），第三方代码必须打进 bundle， 不能远程加载 —— 体积直接影响 newtab 的包。

二、现状里三个"刻意"的设计（也是换库的代价所在）

① 转义优先

流程是「先 escapeHtml → 再做行内替换」。 正文全部来自模型，是不可信输入；这个顺序让 <script>、带 onerror 的 <img> 结构性地只能落成可见文本。 链接只放行 http/https/mailto，其余降级成纯文本。

这比"先渲染、再用 DOMPurify 过滤掉已知坏东西"强一档： 前者是"不可能发生"，后者是"过滤掉我们想得到的那几种"。

② 输出 token，不是 HTML 串

markdownToBlocks() 返回块数组（p / heading / code / list / table / quote / hr），由 Vue 模板逐个渲染。因此：

  • 每个代码块能挂自己的复制按钮（T-128）；
  • 表格委托给 AgentTable，带着 T-156 的溢出提示守卫；
  • 代码文本走 Vue 插值（自动转义），不需要 v-html。

库给的是 HTML 串 —— 这三样都要重造。

③ 流式增量解析

createMarkdownStream() 只重解析最后一个未完成块， 已完成的块缓存。实测（T-14，本机 node）：

  • 单次解析线性，约 0.55 ms / 万字（不掉帧）；
  • 整段重解析的累计成本随长度平方增长：20K 字按 40 字/delta 累计 313 ms，按 10 字/delta 1.1 s 主线程时间；
  • 只重解析最后一块：同样输入约 4 ms（约 70 倍）。

六、决策与落地（2026-10-09）

结论：上库 —— 但走"库做词法、渲染自己出"的混合路线，而不是 上面设想的 marked + DOMPurify。

本稿原先把"上库"等同于"用 marked.parse() 吐 HTML、再拿 DOMPurify 过滤"，于是把它判成"安全降档 + 三处重造"。真正落地时发现 还有第三条路，而它把这两笔代价同时绕开了：

  • 解析交给 marked 的词法器（Lexer.lex / Lexer.lexInline），只拿 token 树；
  • 渲染仍由自己逐 token 拼 HTML —— 白名单以外的 token（含源码里 手写的 <script> / <img onerror>） 一律转义。

于是三处代价全部消失：安全不变量原样保留（是"结构上不可能注入"， 不是"渲染完再过滤"，所以没有引入 DOMPurify）；token 接口不用重造 （复制按钮仍拿得到代码块原文、表格仍委托给 AgentTable）；流式也不用重写 —— 换的只是 parse 的实现，切点策略一行未动，那 200 组随机切分 等价性断言原样继续跑，并全部通过。

落地清单（已完成）

  1. 解析层换成 marked 词法器，markdownToBlocks 改为 token → 块 的映射（公开 API 五个导出一个没动）；
  2. 列表 depth 按真实层级（不再 Math.min(1, …)）， 子列表递归展开成独立项；
  3. 每项自带 marker，有序/无序可混在同一列表里 —— 修掉"混合嵌套把子项并进父项、改写内容"这条真 bug；
  4. 任务列表：task / checked → 模板画只读复选框；
  5. 有序列表起始序号保留（3. 起就从 3 编）；
  6. 行内多反引号 ``…`` 由 marked 处理；
  7. 守卫：新增 markdownLib.test.js（链路守卫 + 钉死"不许退化成 marked.parse + v-html"）+ 6 条 GFM 能力断言， 变异验证 8/8 命中。

项 结果
