三、这个 UI 写得怎么样

做得好的 8 条 · 有依据

  1. 信息放在「决定发生的那一刻」 目标页 chip 贴输入框上方（发送前要知道读的是哪一页）、水位放元信息行（发送前要知道还剩多少），都不是藏在菜单里。原来的水位在会话下拉里，等于逼用户先开菜单才能决定按不按发送。
  2. 空间是按像素省的，不是靠感觉 header 的箭头只在 hover/focus 出现（320px 里 20px = 标题多两个字）；未配置时元信息行整行隐藏；发送与停止合并成同一个 40px 按钮位，让忙碌与空闲的 textarea 都稳定在 250px（headless Chromium 实测）。
  3. 颜色克制：整套只有黑白 + 一个红 accent 浅色是 24 24 27（近黑）、深色是 244 244 245（近白）。水位分档靠「重量 + 明度」而不是三色；红只用在错误与真正告急两处。
  4. 状态从不只靠颜色 工具卡的 完成 / 失败 / 已拒绝 分别挂 ✓ / ✕ / ⊗ 三个形状不同的图标，颜色退成冗余通道——色觉障碍用户与暗色模式都能分。被拒与失败刻意区分：前者不是模型的错，重试意义完全不同。
  5. 禁用一定给理由 busy 时新建按钮的 title 从「新会话」换成「助手正在生成，暂不可切换或删除会话」；会话列表行容器上也挂同一个 title（disabled 按钮在部分浏览器不派发鼠标事件）。
  6. 浮层不脱离本列 目标页 chip 曾用 512px 的 ui-modal / ui-popover，都因「弹窗比宿主还宽、下拉顶出侧栏、把面板撑开」被换掉，改用留在文档流里的 AgentDropdown。确认门也刻意放文档流，不遮挡输入区。
  7. 溢出治理在叶子上 长 URL / base64 / 单行 JSON 这类无空格长串， whitespace-pre-wrap 断不了。正文 <p> 加 break-words，代码块与表格保留 overflow-x-auto，横向滚动留在叶子内部，外层不再出横向滚动条。
  8. 无障碍不是后补的 transcript 是 role="log" aria-live="polite"；标题带 aria-level；图标按钮都有 aria-label；复制按钮 opacity-0 但 focus 即显形。

值得改的 7 条 · 按优先级

  1. P1 · 琥珀/黄一处三义，警示力被稀释 未配置横幅（黄）、advisory notice（琥珀）、确认门（琥珀边框）三处同一种颜色，语义完全不同：一个是「配置缺失」，一个是「善意提醒」，一个是「要你批危险操作」。建议 notice 降成中性灰（它只是提示），确认门独占琥珀，未配置横幅改用带图标的信息条。已登记 T-152，未决。
  2. P1 · 告急态把元信息行从 24px 撑到 46px ≥95% 追加的「上下文将满，建议新建会话」触发 flex-wrap 换行，正好在「最需要空间看正文」的时候吃掉 22px。建议告急文案改成图标 + 短词（如「将满」）或只进 title，把完整句子留在点开的明细里。
  3. P2 · 用户气泡是唯一一处非黑白用色 bg-blue-500/15 在整套黑白体系里显得跳，而且和「代码块/表格」的灰底拉不开层级差。建议改成灰底 + 右侧 1px 分隔，或把蓝保留但降到与 accent 同权重。
  4. P2 · 工具链没有进度感 工具卡默认全部折叠，跑 7 步时看到的是一叠「完成」，不知道第几步、还要多久。建议：运行中自动展开最后一张；卡片标题带上序号（2/7）或 dots。
  5. P2 · 新建会话只有一个「+」图标 没有文字标签，新用户只能靠 hover title 才知道这是「新会话」。在 320px 里加文字要 40px+，取舍合理，但至少可以让图标换成「+ 会话」的复合图标，或在空态里给一个带文字的入口。
  6. P3 · 轮次分隔线只有时间，没有「第 n 轮」 长会话里翻找定位弱。代码注释里已把它登记为「刻意做轻」的取舍，但压缩卡出现之后（已压缩 6 轮）用户更需要知道自己在第几轮。
  7. P3 · 矮窗口下输入区占比偏高 chip(≈30) + textarea(68) + 元信息行(24) + 队列行 + 确认卡 叠起来，560px 面板里能剩给正文的不到一半。建议在极矮时把 chip 与元信息行收进一个「更多」折叠，或给 transcript 设最小高度下限反过来压缩输入区。

四、组件清单（10 个，全部在 newtab/workflow/agent/ 下）

组件 职责 设计上值得记的
AgentPanel.vue 面板骨架：header / transcript / 输入区 / 元信息行 收单个 host 对象 prop，两个宿主共用，不再逐条绑定
AgentTranscript.vue 事件流 → 渲染槽位，滚动跟随与「回到底部」 折叠逻辑在 agent/fold.js；role=log + aria-live
AgentMarkdown.vue 零依赖 markdown 渲染（标题/列表/代码/表格/引用） 流式增量解析，只重解析最后一个未完成块
AgentToolStep.vue 工具卡：参数 / 观察值折叠，状态徽标 观察值在展示层剥掉 untrusted_* 标记，模型侧照旧
AgentContextRing.vue 14px 水位圆环 + 常驻百分比 算不出来时整段不渲染（不显示 0%）；红只在 ≥95%
AgentTabPicker.vue 目标页 chip（favicon + 标题 + 自动/固定） 失效态整行变红；不做「解除」，因为没有这个状态
AgentSessionList.vue 会话下拉内容：切换 / 删除 / 模型名 每行自带垃圾桶，删历史不必先切过去
AgentConfirmCard.vue 写类工具的确认门（代码/选择器/URL/画布） 放文档流，不遮挡输入区；文案按 kind 取
AgentDropdown.vue 留在文档流里的下拉（替代 ui-popover / modal） absolute 定位，side=top/bottom 可选，不挂 body
AgentTabList.vue 标签页列表（按窗口分组） 每次打开才拉一次，面板可能开着放很久

一句话总结：这是一份把「信息放在决定发生的那一刻」执行得很彻底的 320px 侧栏 UI——位置决策、像素预算、颜色克制都可圈可点；剩下的短板集中在 琥珀一色三用 与 告急态的空间反噬 两处，都是可以小改解决的。
