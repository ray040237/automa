01设计目标与约束#overview

这个助手不是「聊天框 + 一个大提示词」。它是长在浏览器扩展里、能直接读用户当前页面 DOM、能改工作流画布、但永远不能替用户点保存的 ReAct Agent。它的独特性几乎全部来自这个宿主身份。

能力来源

  • 读真实 DOM — 扩展自带 content script，能拿到已渲染的结构，而不是让用户复制粘贴 HTML
  • 执行 JS — browser.scripting.executeScript({world:'MAIN'})，能在页面主世界跑表达式
  • 改画布 — 宿主把 vue-flow 的 editor 实例注入，助手能把块直接放到工作流上
  • 控制标签页 — 跨页任务：A 页读数据、B 页填表

硬约束（红线）

  • G5：agent 永不保存工作流 — 只能改内存画布并置 dirty，保存永远是用户自己点的
  • 第三方内容一律 untrusted 包裹 — 页面正文/工具返回/用户输入回显进 prompt 前必须包标签并逃逸清洗
  • 工具必须显式声明 class: read|write — 模块加载期 validateTools 强制校验，缺声明直接 throw
  • 不静默降级 — 失败要有可读的观察值回喂模型，不许吞异常
一句话概括：一个纯函数内核 + 一层装配 + 一个 Vue 宿主，跑在 MV3 扩展的三个进程里， 通过唯一一份事件历史同时喂给「模型」和「用户」，写操作一律卡在用户确认门上。

两个刻意的分类偏离（ADR 0002）

highlight_selector 归 write（方案原文说 read）。

理由：「模型每说一句就改一次你的页面」本身就该由用户点头 — 而且确认卡上直接显示选择器，用户点「允许」恰好回答了「你说的是这个吗」。把它算成 read 是拿一致性换方便。

focus_tab 归 read（方案原文说 write）。

理由：它只改 agent 内部的目标页指针，不 activate、不导航，风险面与 query_elements 相同；过确认门会把跨页任务的确认次数翻倍而无信息增益。

  agent.busy = true;
  try {
    const result = await agent.runtime.send({
      userText,

        if (ev && ev.kind === 'agent:target-tab') {
          agent.targetTab = ev.tab || agent.targetTab;  // 目标页只更新 UI，不进对话流

      },

    if (result?.usage) agent.usage = result.usage;

      err?.kind === 'config' ? t('workflow.agent.notConfigured') : err?.message });

    agent.busy = false;

function pageFingerprint(url, title, textContent) {
  let input;
  try {
    input = url + '\n' + String(title || '') + '\n'
         + document.querySelectorAll('*').length + '\n'
         + String(textContent || '').length + '\n'
         + String(textContent || '').slice(0, FINGERPRINT_SAMPLE_CHARS);  // 4096
  } catch (e) { input = url + '\n' + String(title || ''); }

  let h = 0x811c9dc5;                       // FNV-1a offset basis
  for (let i = 0; i < input.length; i += 1) {
    h ^= input.charCodeAt(i);
    h = Math.imul(h, 0x01000193);          // FNV-1a prime
  }
  return (h >>> 0).toString(16).padStart(8, '0');
}

刻意不用 innerText — 它要触发样式计算与布局，大页面上每步都算浪费；textContent 不触发 layout，采样 4096 字符足以捕捉 SPA 换路由、翻页、筛选、展开。

function dropOldestTurn(messages) {
  const lastUserIdx = lastUserIndex(messages);

    if (messages[i].role !== 'user') continue;

丢弃单元永远是 (user, assistant, 其后连续的 tool*) 整组，因为 OpenAI 要求 tool 消息与产生它的 tool_calls 配对，只丢一半直接 400。dropOldestStepInLastTurn 是单轮内降级：只在最后一个 user 之后找组，只剩一组时返回 null —「宁可如实超预算（交给 provider 报错）也不要交一份没有现场的上下文」。

quarry 1：[DONE] 早于 tool_calls 收尾

智谱 bigmodel.cn、阿里百炼 dashscope 已知行为。不处理的后果：本轮被当成「模型说完了」，工具永远不执行，agent 静默卡死。所以收尾时先 flushCalls()，再按 stopReason='tool_calls' 结束。

DeepSeek / ModelScope 实测形态：首包带 id + name + 空参数，随后每 chunk 只带 index + 一段参数字符串片段。必须按 index 累积、流收尾时每个调用只 emit 一次完整 JSON — loop 对每条 tool-call-delta 直接 JSON.parse，半截 JSON 会在那里炸掉整轮对话。

16已确认缺陷#defects

以下两条是本次梳理中新发现的，已按 AGENTS.md「发现即登记」写入 docs/backlog.md（T-27 / T-28），未做任何修复 — 需要你审核后才开工。

T-27 — 确认卡的代码框永远是空的

AgentConfirmCard.vue 只接收一个 code prop，而 runtime 存进 pendingConfirm 的 code 取自 req.code。但 loop.js 的 requestConfirmation({ ...call }) 里 call 只有 {step, name, toolCallId, args} —根本没有 code 字段，于是 (req && req.code) || '' 永远落到空串。

影响：所有 write 类工具（test_js / highlight_selector / open_url / add_block / update_block）的确认卡都是「一句 hint + 一个空白框」。用户看不到要跑什么代码、要往画布放什么块。ADR 0002 声称的收益（「用户点允许恰好回答了『你说的是这个吗』」）直接落空，确认门形同虚设。

连带问题：卡片 hint 写死为「这一步会在你选中的页面上执行代码」，而 open_url / add_block 并不执行代码。

证据：代码位置，推断，未实测复现。

17设计取舍速查#summary

决策做法理由（来自代码注释 / ADR）
纯度分层index.js 是唯一碰 browser API 的文件让整个 agent 能被 node --test 直接覆盖，不需要浏览器环境
单源记账只有一份 history，UI 与 wire 都派生两份状态必然漂移；UI 和 wire 重复记账迟早对不上
熔断式降级promptFacts 失败 → 空事实表 + ERROR 事件；预检失败 → 跳过「模型少知道一点，但还能继续对话」比整个功能死掉好
advisory 而非 gate预检产 system-notice，不硬停任务良性重定向链会误杀；由模型自决去留
错误即观察值工具抛错 → status:'error' 喂回模型模型能自纠；抛栈只会让它原地打转
先剔除再裁剪elideStaleObservations → applyTokenBudget反过来的话，12 步单轮整组法一条都丢不掉
截断在包装之前truncateObservation → wrapUntrusted否则砍掉一半的闭合标签会让半个标签暴露
token 估算偏保守1.5 / 0.7（原实现 2.5 / 1.2）低估让压缩触发太晚（请求直接失败）；高估只是多压一次
保守的权限默认值未知工具 → 需确认；缺 class → 加载期 throw「权限判定上的不确定，一律往更保守的方向倒」
锁不是安全边界tabLocks 只在跑一轮时持有「UX 防误伤，不是安全边界：双方都是同一个用户的 BYOK 扩展」
SSE 用外部依赖eventsource-parser手搓分帧漏掉边界「不报错，只是静默丢消息」
绕开 fetchApi两处都用原生 fetchBYOK 不是 Automa 云端，离线版应当可用
thinking 不进 wirewire.js:80-83 直接 break多数兼容端点不认 reasoning 字段，混进去会被当正文展示给用户
索引不带 eventsagent_session_index 独立画一个会话下拉框不该把全部历史读进内存

一条完整的心智模型

把 agent 想成一个「受限的浏览器自动化 IDE 副驾」：

它能读页面（content script）、能改画布（vue-flow editor）、能跑代码（MAIN world）、能管标签页（tabs API）—— 这四样就是它的能力边界。

它改内存不改磁盘（G5），是第一道约束；
它所有写操作必须有人点头（确认门），是第二道；
它把一切外部文本都当数据不当指令（untrusted），是第三道。

三道约束互相独立、互不依赖 — 这才是这个设计真正的稳健之处。 也正因为互相独立，T-27（确认门形同虚设）与 T-28（三个工具打不通）才会各自成为单点失效。
