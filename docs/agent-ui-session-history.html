Agent 会话历史设计稿 · 从「浮层里的一个列表」到「一个视图」

承接上一轮的判断：目标页是状态指示器（高频、可逆），会话历史是历史导航（低频、需要浏览与搜索、删除不可逆）—— 两者共用 AgentDropdown 只是因为都被关在 320px 侧栏里，不是因为交互语义相同。 本稿只处理会话这一半。所有文案取自 src/locales/zh/newtab.json → workflow.agent.session，字段取自 sessions.js 的索引条目。

0 · 先说一个推翻我上一轮建议的发现

上一轮我说「历史迟早需要搜索」。读完存储层发现 搜索能搜到的东西比我以为的少得多： 会话索引条目只有 { id, workflowId, title, status, createdAt, lastAccessedAt, messageCount } ——不含 events（indexEntryFromSession 刻意不带，否则列表一次读就是全量历史）。 而 title 来自首条用户消息的前缀，被 truncateTitle 截到 24 字符（title.js:9）。

所以： 搜索只能匹配 24 字以内的标题前缀，搜不到正文。 这不是设计选择，是数据结构的约束。设计上必须如实呈现——搜索框的 placeholder 就写「搜索标题」，空结果时说明原因，不要假装它是全文搜索。
这个约束反而把重心推到了别处：既然标题信息量低（24 字、还都是「帮我把这个页面的…」 这种开头），找一条历史真正靠的是时间和规模。所以本稿的主角是 时间分组 + 消息数，搜索只是配角。

5 · 交互细节与坑

话题 规则
进入 / 返回 点 header 的会话名进入历史视图；返回键回到对话。切视图不卸载 transcript 组件 —— events 还在 host 上，回来不用重放。 进入历史时 composer 隐藏（不是 disabled）：这时候不该让人以为能打字。
切走的代价 得说清 openSession 里 instructionQueue.length = 0 —— 切会话会丢掉还没送达的插话。如果 pendingInterjections > 0，选中一条时该提示一句， 不能默默扔掉。
忙碌态 搜索与浏览不限；「选中」和「删除」置灰，hover 显示 session.busyHint（助手正在生成，暂不可切换或删除会话）。 比现在整个下拉 disabled 好：生成时也能翻历史。
删除 保留「每行自带删除」，不用先切过去。确认弹窗沿用现有两句文案。 删的是当前会话时，删完回到空会话态（现有 deleteAgentSession 已处理）。
时间分组 今天（HH:mm）/ 昨天（昨天 HH:mm）/ 更早（MM-DD）。项目里 没有相对时间文案也没有 dayjs（我查过 locales，只有两处无关命中）， 所以要新增纯函数 + 文案键 —— 见落地清单。
会话归属 侧栏宿主 sessionWorkflowId 有值 → 只列该工作流的会话； 独立助手页 getWorkflowId() => null → 全局列表。这条不用改，但列表要让人看得出归属： 独立页可在分组标题旁标「全部工作流」，侧栏不用标（本来就只有一个）。
触屏 风险 删除键 hover 才出现在触屏上够不到。两个选择：a) 触屏宿主（用 (hover: none) 媒体查询）常驻显示；b) 干脆常驻。 建议 a，桌面侧栏是主场景。

6 · 一个意外的收益：视图化顺带修掉了测试盲区

utils/sfc-render.mjs 把 agent-dropdown 放在 GLOBAL_STUBS 里，slot 不渲染 —— 也就是说，现在整个会话列表在渲染测试里是看不见的， 任何关于它的 UI 断言都得靠静态 grep。历史一旦从下拉 slot 里搬出来成为 独立的正文区组件，它在 panelRender 里就变成真实节点， 能断言「当前会话有 ✓」「空态出 session.empty」「搜索无结果出提示」。这是视图化最硬的一条工程理由，比「浮层不适合浏览」更实在。

7 · 落地清单

要动的文件

  • AgentSessionHistory.vue（新增）—— 历史视图本体：搜索框 + 分组列表 + 空态，props 收 sessions / currentSessionId / busy， emit select / delete / new。
  • AgentSessionList.vue —— 行改成两行密度 + hover 删除 + 当前 ✓；或由新组件取代，旧的留在下拉场景（若有）。
  • AgentPanel.vue —— 新增 view 状态 （'chat' | 'history'）：header 换标题与返回键、 正文区 v-if 切换、composer 在 history 下隐藏。
  • src/agent/sessionGroups.js（新增，纯函数 + 单测）—— groupSessionsByDay(entries, now)、 filterSessionsByTitle(entries, q)、 relativeTime(ts, now)。分组逻辑必须能被单测钉住 （跨天、跨年、空列表），写在 .vue 里一条都测不到。
  • src/composable/agentHost.js —— 加 layout 字段（'narrow' | 'wide'）；独立助手页传 wide。
  • locales zh/en —— 新增 session.history「历史会话」、 session.searchPlaceholder「搜索标题」、 session.searchLimit（正文搜索不到的说明）、 session.groupToday / groupYesterday / groupEarlier、 session.turnCount「{n} 条消息」、 session.deleteOne「删除这条会话」。 sessionOptionLabel 保留 —— header 的 chip 还在用它。
  • 测试 —— sessionGroups 单测（分组/搜索/相对时间边界）； panelRender 断言视图切换与列表渲染（现在终于看得见了）。

可选：要不要让搜索能搜正文

  • A（推荐，零迁移）：只搜标题，UI 上如实说明。24 字前缀 + 时间分组 + 消息数，够用。
  • B（要动存储）：给索引条目加 firstUserText（或 searchText），写入时截取首条用户消息前 100 字。 老条目没有这个字段 → 读取时退回 title，不需要迁移脚本， 只是老会话搜不到正文。代价是索引体积变大（每条 +100 字）。

不在本版做

  • 会话重命名 —— 24 字标题是 LLM 从首句生成的，用户改不了。 历史视图里加「重命名」是很自然的下一步，但要先有 patchTitle 之外的写入通道（它现在只服务 LLM 回写）。
  • 按工作流筛选（独立页的全局列表）—— 侧栏宿主天然按工作流过滤， 独立页全局。要不要在独立页给个筛选器，取决于会话会不会跨工作流攒多， 现在数据不够，先不做。
  • 目标页那半 —— 已在 docs/agent-ui-composer-redesign.html 单独出稿， 与本稿正交。
