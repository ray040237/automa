1认识 Automa

Automa 是一款浏览器扩展，通过把一个个「块（Block）」用连线串起来，实现自动填表、重复操作、网页数据抓取、截图、定时任务等自动化工作流。

可视化编排
61 个内置模块覆盖网页交互、浏览器控制、数据处理、条件循环与在线服务，无需写代码即可完成大部分自动化。
定时与事件驱动
支持间隔、Cron、指定日期/星期、访问特定网址、浏览器启动、右键菜单、键盘快捷键、元素更改时等 10 种触发方式。
结构化数据
内置「表格 + 变量 + 全局数据 + 凭据」数据体系，采集结果可直接导出 JSON / CSV / 纯文本，或写入 Google Sheets。
双浏览器支持
同一套代码构建 Chrome (Manifest V3) 与 Firefox 版本，仓库位于 AutomaApp/automa。

4核心概念

4.1 一个工作流由什么组成

trigger触发器→ new-tab新建标签页→ event-click点击元素→ get-text获取文本→ export-data导出数据
  • 必须有且仅有一个触发器块，工作流从这里开始；一个块默认只允许 1 条输出连线（并行分支除外）。
  • 连线方向 = 执行顺序。禁用（disableBlock）的块会被引擎直接跳过。
  • 部分块有 2 个输出端口：第 1 个是「真 / 正常」分支，第 2 个是「假 / 异常 / 否」分支 —— 典型如「条件」「元素存在」「While 循环」「HTTP 请求」「重复任务」。

5数据与表达式

这是 Automa 最核心也最容易踩坑的部分。所有块配置项中，只要在源码里登记了 refDataKeys，就支持用 {{ }} 引用运行时数据。

5.1 六类数据源

数据键含义生命周期
table工作流的数据表格，由一组带类型的列组成，行由各块写入时自动追加单次运行（可被「复用上次状态」持久化）
variables变量，键值对形式单次运行
globalData全局数据，一段自由格式的 JSON 文本，在侧边栏编辑工作流级，随工作流保存
secrets凭据，加密存储，引用时自动解密全局，跨工作流
loopData循环数据，每个循环块在运行时生成一条单次运行
googleSheetsGoogle Sheets 块读取到的数据，按参考键存放单次运行
workflow工作流自身信息（名称、ID 等）单次运行

5.2 表格与列

  • 表格在编辑器侧边栏「表格」面板中定义：列名 + 数据类型。
  • 列的类型共 5 种：Any（不转换）、Text（转字符串）、Number（去非数字后转数字）、Boolean（转布尔）、Array（转数组）。
  • 写入时，若某列还没有对应行，则自动追加新行；每列独立维护自己的行指针，因此多个块可以分列写入同一张表。
  • 未指定列的块，在开启「插入到默认列」时会写入名为 column 的默认列。

表格路径的解析规则（重要）

写法解析为说明
{{table.name}}table[0].name不写索引时默认取第 0 行，容易误用
{{table.0.name}}table[0].name显式索引
{{table.2.name}}table[2].name任意行
{{table.$last.name}}table[长度-1].name最后一行
{{dataColumns.name}}table[0].name别名，等价于 table
注意：若想引用「当前循环写入的那一行」，请在「循环数据」循环中改用 {{loopData.<loopId>.data.字段}}，而不是 {{table.字段}}。

5.3 变量

  • 在块的「赋值到变量」中填入变量名即可写入；带 $push: 前缀（如 $push:list）表示追加到数组。
  • 变量名以 $$ 开头时，会同时持久化到全局变量库（IndexedDB），跨工作流可用，引用写作 {{variables.$$名字}}。
  • 不写前缀的变量仅在本次运行内存在，写作 {{variables.名字}}。
  • 嵌套结构用点号访问：{{variables.user.name}}。

5.4 内置函数（16 个）

函数以 $ 开头，参数中的引用要用双方括号 [[ ]] 包裹以便先求值：

函数用途示例

$randint(min,max)区间随机整数$randint(1,10)

6触发器 Trigger

触发器决定工作流「什么时候跑」。可以添加多个触发器，任一满足即启动；浏览器启动和右键菜单全局各只允许一个。

6.1 工作流参数（Parameters）

触发器块可定义一组「参数」，让同一份工作流在运行前接收外部输入：

  • 在触发块设置中点击 Parameters 添加参数（名称、类型、默认值等）。
  • 运行工作流时若缺参数，Automa 会弹出输入面板（也可勾选「优先在标签页中输入」直接在网页上填）。
  • 由 参数提示（Parameter prompt） 块在流程中间再次向用户索取输入，带超时（默认 60 秒）。

6.2 用 Public ID 从外部触发

在「工作流设置 → Workflow public ID」填入一个 ID 后，任意网页可用自定义事件触发该工作流：

window.dispatchEvent(
  new CustomEvent('你的 Public ID', { detail: { /* 可选参数 */ } })
);
若工作流设置了 type: manual 之外的非定时触发器，导出时同样会保留触发配置。

8条件与控制流

8.1 条件构建器

「条件」块用可视化构建器组合判断，结构为：取值 → 比较方式 → 期望值，多个条件之间可选 AND / OR。

可取值类型

  • 值 — 手动输入，或用 {{}} 引用变量 / 表格
  • 代码 — 写一段返回布尔值的 JS（默认上下文：背景页），支持顶层 await 与 automaRefData
  • 数据存在 — 判断 {{路径}} 是否有值
  • 元素文本 / 存在 / 不存在 / 可见 / 屏幕内可见 / 屏幕内隐藏 / 属性值 — 在页面上直接判断元素

比较方式（16 种）

  • 基础：等于、等于（忽略大小写）、不等于
  • 数值：大于、大于等于、小于、小于等于
  • 文本：包含、包含（忽略大小写）、不包含、不包含（忽略大小写）、开头为、结尾为、匹配正则
  • 布尔：为真 / 为假
重试机制：条件块可开启「不满足则重试」，设置重试次数与间隔 —— 适合等待异步加载的页面，配合「刷新条件连线」可重新读取元素。

8.3 分支与并行

  • 从块的同一个输出端口拖出多条连线 = 并行分支，同时执行。
  • 需要「等所有分支跑完再继续」时，在汇合处插入等待连接块。
  • 模块组（blocks-group）可以把分支打成一个整体，但内部不能放触发器、循环、条件等控制块。

10JavaScript 代码块

当现有模块不够用时，用「JavaScript 代码」块直接写代码。它有两个执行上下文：当前标签页（注入到网页）与背景页（扩展 Service Worker 上下文，可访问扩展 API）。

10.1 可用函数

函数签名说明
automaNextBlock(data?, insert?)结束本块并继续下一个块。data 写表格，insert 写变量；$error:true 表示抛错
automaSetVariable(name, value)设置变量；name 以 $push: 开头则追加
automaRefData(keyword, path?)读取运行时数据，如 automaRefData('variables','userName')
automaFetch(type, resource)以网页身份发起请求，type 为 text / json / base64，绕过跨域限制
automaExecWorkflow({ id })从代码中启动另一个工作流
automaResetTimeout()重置本块的执行超时计时（异步任务用）

10.2 代码示例

// 1) 抓取并写入表格（不写 automaNextBlock 时会自动调用）
const titles = [...document.querySelectorAll('.item .title')].map(el => el.textContent.trim());
automaNextBlock({ data: { title: titles.join(' | ') } });

// 2) 写入变量 + 读取变量
automaSetVariable('$push:titles', '标题一');
const last = automaRefData('variables', 'titles');
automaNextBlock({ insert: { last } });

// 3) 异步：等待条件成立再继续（需重置超时）
const wait = (ms) => new Promise(r => setTimeout(r, ms));
let el = null;
for (let i = 0; i < 20 && !el; i += 1) {
  automaResetTimeout();
  el = document.querySelector('.done');
  if (!el) await wait(500);
}
automaNextBlock({ insert: { ready: !!el } });

// 4) 主动抛错，交给块的「出错时」策略
if (!document.querySelector('#result')) {
  automaNextBlock({ data: { $error: true, message: '未找到结果节点' } });
}
注意：代码块有超时（默认 20 秒）。若代码是异步的，务必在等待循环里调用 automaResetTimeout()，否则会被判定超时失败。
调试：「预加载脚本」会在主代码之前注入页面，可放第三方库；勾选「每次新建标签页都执行」可让脚本在后续新开的页面中常驻。

15常见问题

问题解答
工作流跑到一半就停了？多半是超过「工作流超时」或浏览器把 MV3 后台页挂起。把执行环境改为 Popup，并调大超时。
找不到元素？开启「等待选择器」并延长超时；对动态渲染的页面，用「浏览器事件 → tab:loaded」或「条件 + 重试」等待渲染完成。
循环只跑了一轮？循环体末尾缺少「循环断点」，或断点的循环 ID 与循环数据块不一致。
表格里数据串行 / 覆盖了？同一列的多次写入会逐行追加；若要写同一行，请显式指定行索引（如 {{table.0.x}}）。
CSV 在 Excel 里中文乱码？「导出数据」中勾选「添加 UTF-8 BOM」。
选择器失效？避免依赖自动生成的 class 名（常含哈希），改用稳定的 id、name、data-* 属性或 XPath。
修改了工作流但运行的是旧版？记得保存（Ctrl+Shift+S）；若开启了「执行时自动保存」则无需手动保存。
换设备后工作流不见了？使用「设置 → 备份工作流」导出备份文件，或登录账号做云备份。
想复用一段流程？封装成块包（Packages 页面），或改用「执行工作流」块调用子流程。
