① 琥珀/黄色被三种语义共用，警示退化

当前 notice（善意提醒）、确认门（必须你裁决的写操作）、未配置 API Key（功能不可用）三卡配色几乎一致。语义天差地别却看不出区别——与 T-04 当年给 error 换红色是同一个毛病。

改法：notice 退中性灰（advisory）；确认门升主色蓝 + 明确双按钮（需你行动）；未配置改红色（阻塞）。零逻辑风险，纯 class 调整。

② 用量数字缺标签 + 水位只有两档

AgentSessionList.vue:80-107：用量显示为裸的 1.2K/3.4K，哪个是输入哪个是输出只有 hover 才知；水位条只有「蓝 / ≥90% 红」两档，接近上限前无渐进警示。
当前
1.2K/3.4K上下文 18%
水位 ≥90% 才变红，70~90% 无任何提示。
改后
输入1.2K输出3.4K上下文 18%
三档：＜70 蓝 / 70~90 琥珀 / ≥90 红。
改法：加「输入 / 输出」小标签；水位阈值改三档。纯 UI，不改 usage.js 的计算（那里有单测）。

AgentTranscript.vue:41-69 与 :149-173：两种卡结构、配色、箭头完全一致，但一个是「模型怎么想」，一个是「上面那些历史被压成了一段」——用户分不清。

④ 其余（未在此稿演示，需评审）
