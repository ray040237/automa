# 0001 — Agent 入口为独立主面板标签页

日期:2026-10-03
状态:已实施(未提交)
关联:docs/agent-assist-tech-design.md(被部分取代)

## 背景

agent 最初按技术方案实现为**工作流编辑器内的一个标签页**(`[id].vue` 的 `ui-tab-panel value="agent"`),会话按 workflowId 分组,画布工具(add_block / update_block / list_canvas)依赖编辑器宿主注入的 vue-flow editor。

实际使用中暴露的问题:

1. 助手的使用场景大多与"当前正在编辑的这个工作流"无关(问页面结构、写 selector、聊方案),却必须先进入某个工作流的编辑器才能发问;
2. 会话按 workflowId 强隔离,用户在 A 工作流里问过的问题到 B 工作流"消失",而多数问题本不该有这种归属;
3. 编辑器内 tab 的 keep-alive 依赖 `ui-tab-panel cache`,与主面板标签页体系是两套并行的保活机制。

## 决定

1. **单入口**:撤除工作流编辑器内的 agent 标签页,助手只从主面板标签栏进入。
2. 主面板标签栏的 `+` 改为弹层,两个选项:新建工作流(原行为)/ 打开助手。
3. 助手为路由 `/agent`(挂在 WorkflowContainer children 下,获得 tab 栏外壳与 keep-alive),标签页**单例**——已开着再点只激活。
4. **会话全局化**:`getWorkflowId: () => null`,会话列表不再按工作流过滤;历史编辑器内创建的会话出现在全局列表中。
5. **工具组过滤**(`enabledGroups`):独立助手页注册 `['page', 'context', 'tab']` 组,canvas 组不注册,提示词事实表(promptFacts)随同一份过滤后的列表裁剪——模型不知道有画布工具存在。loop 与工具实现零改动。

## 被拒备选

- **双入口(编辑器 tab + 独立页并存)**:需要抽 `useAgentPanel` composable 供两处复用,且同一份会话列表要处理"按工作流过滤"与"全局"两种视图;独立页与编辑器页的行为差异(画布工具有无)会让用户困惑"为什么这里能加块那里不能"。等画布编辑能力真正进入独立页的需求出现时再重评。
- **助手页绑定某个工作流(路由带 workflow 参数)**:形态上只是把编辑器 tab 搬个位置,问题 1/2 原样保留。

## 已知欠账

- 独立助手页当前**没有画布编辑能力**(add_block 等被过滤)。恢复方式:做一个"在助手里打开某工作流"的挂载机制后放宽 `enabledGroups`,届时需重新评估确认门文案(现在写的是"改完不保存,用户自己检查")。
- 已有的按工作流会话未做来源标注,与全局会话混排。
