二、错在哪几点（逐条核对）

#错误原因修复方向难度
1 浅色下面板根是 #F0F2F5（= bg-shell 亮值），比浏览器 chrome 还浅 → 白卡浮在浅灰上 bg-shell 是 dark-only 抽象，亮值不该挂任何东西 —— 我留了"将来白壳"的占位值，结果漏到了浅色侧栏 删 --color-shell 亮值，浅色下面板根就回到 bg-canvas，与 chrome 衔接 小
2 深色下面板根走 bg-shell（#1F2125，与 chrome 几乎同色），composer 是 bg-surface（#14171C，比 shell 深一档）→ 卡片是凹进去的，深色观感 暗色下"卡片 = 更浅"是 pie 的隐含约定，surface < shell 在暗色下反过来 深色下也用 bg-canvas（#0B0D10）作面板根；让 surface 是 #14171C 浮起，field 是 #1A1E25 再浅一档。三层关系恢复成"由深到浅 = 由远到近" 小
3 composer 提示文案「Enter 发送 · Shift+Enter 换行」 与「↓ 回到底部」按钮挤在同一区域，看起来像"两个差不多的控件" 这是用户截图里那个 < 的来源 —— 实际是 ↓ 浮在代码块 复制 旁边，与上方 composer 提示 Enter 发送 三件东西视觉上撞在一起 提示搬到 composer 顶是对的；回到底部用更轻的形态（去掉按钮或改图标位置）；代码块复制只在 hover 时显形，不要常驻 中
4 深色下 shell 表面 #1F2125 对比 chrome 实际是 #202124（差 1 RGB 单位）→ 几乎看不出明度差，"白卡浮在深壳上"被换成"白板（chrome）vs 白板（shell）" shell 值是猜的（基于 Chrome 较新版本），老 Chrome / Firefox 侧栏 chrome 是 #1F2125，新 Chrome 是 #202124。Shell 必须覆盖更广的色域 不引 shell token，用 bg-canvas 直接吃下两种 chrome 的色差（panel 比 chrome 略浅一档 —— 看着像"嵌在 chrome 里"而不是"覆盖 chrome"） 小

三、为什么 T-212 整体方向是对的

尽管 bg-shell 这个具体 token 是错的，但 T-212 的**观感决策**（在用户答"做第二步"之后做的）大部分都对：

决策对不对说明
用户气泡 bg-accent/10 对 蓝透明是「标签/通知」语义色，用户自己发的话用 accent 更准
工具徽标去底色 + 去边框，只字色 + 图标 对 三个「完成/失败/完成」并排像表单错误列，去框后视觉重量退到正确档
工具卡外壳 bg-field 去外框 对 「这一行和正文不一样」的信号靠底色差，不必再画边框
composer 卡去 border 对 canvas→surface→field 三层关系靠底色差看得出
composer 提示搬到顶部 对 底行只剩「圆环 + 发送」两个控件，层级清晰
新增 bg-shell token + dark 面板根走 shell 错 用 shell 解决的是「白卡浮在深壳上」，但深色 chrome 与 shell 的色差无法预测；改用 bg-canvas 让 panel 始终比 chrome 略浅一档，三层 token 自洽

四、目标态的具体规格（下一步要落地的）

token 层

  • 删 --color-shell 全部定义（亮暗都删），删 tailwind.config.js 的 shell 字段。
  • 面板根的 useAgentHost 不再需要 shell 字段 —— host.shell 删，AgentPanel.vue 的 shell computed 删，面板根 class 回到 bg-canvas 写死。
  • 侧栏 App.vue 根 <div> 去掉 bg-shell，回到原来的 class="h-screen w-full"。

布局层（用户截图里能看到的）

  • 代码块复制按钮 只在 hover 时显形（opacity-0 group-hover:opacity-100 已存在，但常驻时仍可见 —— 看截图判断是常驻态显示的，移出 hover 仍在那里）。改用 group-hover + focus-within 同时挂，鼠标移开、代码块失焦都立即消失。
  • 回到底部按钮 居中靠下（已经这样），但 图标 + 文字 比 单图标轻，文字 text-fg-2 即可；hover 时加 bg-field 反馈。
  • 回到底部 与 代码块复制 视觉重量调到不同档（一个是浮层的"动作"，一个是代码块旁的"动作"）—— 不在同一行对齐就能避免用户截图里那种"两件东西挤一起"的错觉。

守卫层（要改 / 加的）

  • 删 T-212 守卫里的"shell"相关条款（面板根、useAgentHost、sidepanel、--color-shell）。改回"面板根必须 bg-canvas"的单条断言。
  • 代码块复制按钮的常驻态加守卫：class 串里必须有 group + group-hover:opacity-100 + opacity-0（钉"hover 才显形"）。

五、要看的两个对照

左：当前实际状态（bug）。右：目标态（fix）。差异肉眼可见 ——

浅色对比（侧栏 chrome 也是浅色）

当前：「白卡浮在浅灰上」 —— shell 比 chrome 浅，composer 又比 shell 白，三层都偏白，看着像弹窗。目标：取消 shell，面板根直接 bg-canvas（#FAFBFC，与 chrome #ECEEF1 差 4 RGB 单位），composer 浮起，input 凹陷 —— 三档明度差清楚。

深色对比（侧栏 chrome 是深色）

当前：bg-shell（#1F2125，与 chrome 同色） + composer bg-surface（#14171C，比 shell 深）—— 卡片是"凹下去"的，反直觉。目标：面板根 bg-canvas（#0B0D10，比 chrome 略深），composer bg-surface（#14171C，比 canvas 浅）—— 卡片是"浮起来"的，符合预期。
