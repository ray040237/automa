2三档配色与 hover 文案（放大示意）

实测修正：项目主色 --color-accent 浅色下是 24 24 27（近黑）、深色下是 244 244 245（近白）—— accent 本身就是黑白，整套 UI 也只认这一个色。所以三档不靠颜色， 靠粗细：常态细环、接近上限加粗，只有真要到顶才用红（红在本面板已有 明确语义 —— T-04 把 error 从琥珀改成红，不该再拿去做装饰）。

实现的三件事
① 环 = <svg> 两圈 <circle>，stroke-dasharray = 周长、stroke-dashoffset = 周长 ×(1−pct)， rotate(-90deg) 从 12 点起画。无需依赖，与项目「零依赖自研 markdown」的取向一致。
② 档位由 @/agent/usage 的 contextPercent 判定 —— 它已有单测，计算层不动，只加显示分支； 三档是 stroke-width 2 → 3，配 text-accent（项目主色， 本身就是黑白）→ text-red-500，不引入蓝/琥珀。
③ 无障碍：环加 role="img" + :aria-label（读屏读到完整句子）， :title 只服务鼠标 hover；两者不重复朗读。

3还有哪些地方能省空间 / 该顺手修

按「能省多少 × 风险」排序。前三条是纯 class / i18n，零逻辑风险；后两条要么要实测、要么牵逻辑。

输入框 min-h 88 → 68 常态省 20px 零风险

空草稿时输入框钉死 88px（三行观感）。autoresize 会随内容长到 max-h-128，所以这 20px 只在草稿短时占用，却永久从 transcript 里扣。改成 68px（两行观感）后，长草稿行为完全不变。

嫌窄可取 72px（省 16px）。若担心「输入框太矮不像能打长指令」，可只在 host.busy 或草稿为空时保持 88 —— 但那是加分支，建议先按定值试。

落点 AgentPanel.vue:169 min-h-[88px] → min-h-[68px]

会话 chip 的下拉箭头改为 hover 才显 横向省 20px 零风险

箭头 riArrowDownSLine 恒占 14px + gap 6px。在 320px 宽里这是 chip 标题能多显示 2–3 个字的差别，而「标题 · 时间」正是被 truncate 截断最狠的地方。改成 group-hover:opacity-100 opacity-0（键盘 focus 时也要显， 用 group-focus-within 兜住）。

代价：静态时 chip 少一个「可点开」的视觉暗示 —— 但项目里 46+ 处 bg-box-transparent 已经承担了这个暗示，箭头不是唯一线索。

落点 AgentPanel.vue:33-36（箭头 span 加 transition opacity + group/group-hover）

未配置 API Key 横幅压成一行 该态省 16px 零风险

现在是 p-3 text-sm 整行（约 44px）。它是阻塞态没错，但发送按钮 已经 disabled 了，横幅只需要一句「发送已禁用 · 去设置」—— px-2 py-1.5 text-xs 足够。与 T-152 的「改红」合并做。

顺带：这行也是唯一会把「功能不可用」与「善意提醒」混淆的地方（T-152）， 改红后语义才立得住。

落点 AgentPanel.vue:87-94（p-3 text-sm → px-2 py-1.5 text-xs，配色随 T-152 改红）

busy 态输入区被两个按钮挤到 208px 需实测

host.busy 时 form 里同时有「停止」图标按钮 + 「插话」文字按钮： 320 − 16(padding) − 36(停止) − ≈44(插话) − 16(gap) ≈ 208px 留给 textarea，比空闲时的 240px 还窄。而 busy 恰恰是你最想打字（插话）的时候。

可选方向：插话按钮在窄态退化为图标 + title；或把「停止」并入 已存在的 pendingInterjections 行（:148）。我没有实测过 320px 下的真实换行，建议先量一次再定，别凭估算改。

落点 AgentPanel.vue:173-191

disabled 的发送按钮说不出「为什么点不动」 需评审

:186 是 :disabled="!draft.trim() || !configured"，但按钮上没有 title。 项目自己在 AgentSessionList.vue:17-18 注释里写过「disabled 按钮在部分浏览器不派发鼠标事件、title 弹不出来」——同一个面板里这条经验没贯彻到发送按钮。

建议照抄 T-11 的做法：把 title 挂到非 disabled 的包裹层上，文案按 原因分两种（没草稿 / 没配 Key）。纯属性，但要区分两种原因，属小逻辑。

落点 AgentPanel.vue:183-191（包一层带 :title 的容器）

slash 菜单 max-h-48 可能吃掉半屏 需实测

模板菜单最高 192px，出现在输入框正上方。面板总高若只有 500–600px， 它会把 transcript 压掉三分之一。建议改成 max-h-[30vh] 或按条目数封顶（如 5 条 ×28px + padding）。

未实测：我不知道真实模板数量与面板实际高度，改小可能让长列表难用。 先量，再定。
