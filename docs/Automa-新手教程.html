⚠️陷阱：书名被截断了

页面上看到的书名是 A Light in the ...，因为网站为了排版把长标题省略了。完整书名其实藏在 title 属性里。

所以抓书名要用「属性值」而不是「获取文本」。这是新手最常踩的第一个坑 —— 而且它揭示了一个通用规律：

  • 屏幕上看得到的内容 → 获取文本
  • 链接地址、图片地址、title / alt / class 等 → 属性值

2抓取网页元素（原子操作）

本章你会做什么：学会在任意网页上抓一个元素，并且知道抓不到时该怎么办。
这一章只有一个新概念：元素选择器。

2.1　什么是「元素选择器」

网页是由一个个「元素」堆起来的标签。任何抓取动作，本质都是告诉机器"去页面上找哪个元素"，这个地址就叫元素选择器。

方法一 · 用鼠标点（推荐新手）

  1. 打开练习站任意一页
  2. 按 Alt+P，或点工具栏 Automa 图标 → 中间的 ◎ 按钮
  3. 鼠标移上去，页面元素会高亮，鼠标点一下
  4. 它会给你一段选择器，复制下来，粘贴到任意模块的选择器框里

方法二 · 自己写 CSS 选择器

练熟之后更快。够用的四条：

写法含义例子
标签名按标签找h1   p   a
.类名按 class 属性找.price_color
#id按 id 找（最稳，优先用）#product_description
空格「里面」—— 后代选择器.product_pod h3 a
💡 写选择器的顺序

先用鼠标点出来，再照着改。别一上来就手写 —— 那是新手最大的时间黑洞。

2.3　抓不到元素怎么办（第一次接触「等待」）

练习站是静态页面，一抓就有。但真实网站经常是"打开时还是空的，数据过一秒才刷出来"。这时候你会看到报错 element-not-found。

💡 解法：勾上「等待选择器」

在模块设置里勾选「等待选择器」，Automa 就不会立刻放弃，而是每隔 0.2 秒重试一次，直到元素出现或超时。

几乎所有"网页交互"类的模块都有这个开关，建议默认都勾上，并把超时设成 5 秒。

⚠️ 陷阱：它只等「第一个」，不等「全部」

只要页面上出现一个符合条件的元素，它就立刻返回 —— 哪怕页面上本来应该有 20 个、现在只加载了 3 个。

所以做列表抓取时，光靠"等待选择器"是不够的，要用第 3 章的循环 + 加载更多。

3抓一组列表（多个并列元素）

本章你会做什么：把一整页 20 本书（甚至 50 页 1000 本）抓下来。
本章引入两个新概念：多选 和 循环元素。记住这一条原则：
能用「多选」解决，就别用循环。
循环是给"必须一条一条做不同操作"准备的。单纯抓数据，多选一行就够了。

3.0　第一步想清楚：选择器要指向「重复项」本身

页面上有 20 本书，每本书是一个 <article class="product_pod">。想一次全抓走，选择器就填这个重复项的类名：

.product_pod          ← 对，抓 20 个「书」
.product_pod h3 a     ← 这是 20 个「链接」，不是「书」

想抓其中某个字段，就把字段选择器接在重复项后面：.product_pod .price_color。

3.1　方法一 · 多选（推荐先用这个）

它是怎么做到"自动对齐"的

这是 Automa 里最值得知道的一个机制。开启「多选」后，一个「获取文本」模块会一次返回一个数组；Automa 看到这个数组，就把每个值分别写成一行。

更妙的是：每一列各自维护自己的行号。所以三个模块各抓 20 条，结果自动排成 20 行 × 3 列，不需要任何对齐操作。

        模块1（书名·多选）      模块2（价格·多选）      模块3（链接·多选）
                 ↓                        ↓                        ↓
        ┌─────────────────────────────────────────────────────────────────┐
  行 0  │  A Light in the...    │   51.77    │  /a-light-in-the-attic │
  行 1  │  Tipping the Velvet   │   53.74    │  /tipping-the-velvet   │
  行 2  │  Soumission           │   50.10    │  /soumission          │
   ...  │        ...           │    ...     │        ...           │
        └─────────────────────────────────────────────────────────────────┘
   每列有自己的行号 → 各自往下写 → 天然对齐

✓ 应该看到：每个模块设置栏里，「多选」是一个可勾选的小方框

4

串成一条线，最后接 「导出数据」（CSV + UTF-8 BOM），运行。

✓ 应该看到：CSV 里有 20 行 × 5 列，价格列是纯数字

⚠️ 陷阱：列的类型千万别选「数组」

如果目标列的类型是「数组」，Automa 会把整个数组塞进一个单元格，而不是展开成 20 行。

只要你是想"抓多行"，列类型就用「文本」或「数字」。

⚠️ 陷阱：某一列多匹配了东西，整张表就错位

比如某个模块的选择器手滑多写了一级，匹配到 25 个元素 —— 那它就会写出 25 行，而其它列只有 20 行，第 21~25 行只有一列有值。

跑完记得扫一眼表格行数：各列元素数量应该一致。不一致就回去检查选择器。

3.2　方法二 · 循环元素（需要"逐条做不同事"时）

什么情况必须用循环？—— 每一本书要做的事不一样，比如：点进详情页抓内容再返回、价格高于 50 才记录、顺手把封面图存下来。

多选做不到这些，因为它只是"各抓各的"，没有"一条一条排队做"。

循环元素是怎么工作的

Automa 在页面里给每个匹配到的元素打一个专属标记，让循环体里的模块只认领"当前这一本"。你不需要关心标记长什么样 —— 循环过程中，{{...}} 表达式会自动把它变成当前项的选择器。

循环开始
  ↓
Automa 给每本书打标记：  book-0   book-1   book-2  ...
  ↓
第 1 轮：循环体里的 {{loopData.book}} = book-0 的选择器
  ↓
第 2 轮：自动换成           book-1
  ↓
   ⋮
  ↓
循环断点 → 回到循环开头，开始下一轮

动手 · 用循环抓 + 判断价格

1

拖一个 「循环元素」，配置：

  • 元素选择器：.product_pod
  • 循环 ID：填 book（自己起，记住它）
  • 要循环的元素：.product_pod
  • 最大循环数：20（填 0 = 不限）
  • 每个元素操作等待时间：3 秒

✓ 应该看到：设置栏里有一个"循环 ID"输入框

2

在循环体里加 「获取文本」，选择器这样写：

{{loopData.book}} h3 a

读作："当前这一本书里面的 h3 a"。每一轮它自动指向不同的书。

✓ 应该看到：运行日志里每一轮抓到的是不同的书名

3

如果要把上一轮的文本填进输入框，写法完全一样 —— 只是把选择器换成了输入框的选择器，比如搜索框：{{loopData.book}} input[name="q"]

4

循环体最后一定、必须接一个「循环断点」，它的循环 ID 也要填 book（和循环元素块一致）。

✓ 应该看到：完整流程是这样一圈

循环元素id=book · .product_pod→ 获取文本{{loopData.book}} h3 a→ 条件价格 > 50 ?→ 插入数据写入表格→ 循环断点id=book ↺
⚠️ 陷阱一：忘了循环断点 = 无限循环

循环体的末尾没有「循环断点」，流程就会一直往回跑，Automa 检测到后报 workflow-infinite-loop 并强制停止。

⚠️ 陷阱二：循环 ID 两边必须一样

「循环元素」填 book，「循环断点」就必须也填 book。不一致同样报无限循环错误 —— 因为引擎找不到对应的循环。

⚠️ 陷阱三：不要多写一层.data

循环体里引用当前项，正确写法是 {{loopData.book}}（要取字段才写 {{loopData.book.名称}}）。

写成 {{loopData.book.data}} 会取不到值 —— 引擎会自动帮你补这一层，不用你操心。

3.3　选哪个？

你的需求用哪个理由
把列表页的数据原样抓下来多选最简单，4 个模块搞定，不用循环
每条数据要筛选一下（比如价格 > 50）循环元素多选没法在中间加判断
每条要点进详情页 / 下载图片 / 发请求循环元素这些是"有副作用"的操作，必须排队一个个做
页面是滚动加载的，抓不到全部循环元素 + 加载更多见 3.4
数据不在网页上，在接口返回里不用循环用「HTTP 请求」更快，见第 14 章

4抓不全：分页与滚动加载

本章你会做什么：把 books.toscrape.com 完整的 1000 本书抓下来，并学会判断"到底抓全了没有"。
这是新手从"能跑"到"能用"之间最真实的一道坎。

4.0　先分诊：你是哪一种"抓不全"？

"抓不全"不是一个问题，是六个不同的问题。先对症状，再看解法，否则会白折腾很久。

你看到的症状真正的原因去看
跑两次，行数不一样页面还没渲染完就抓了4.1
只有第一页，后面没了没做翻页4.2
页面向下滚才出数据懒加载 / 无限滚动4.3
循环莫名其妙提前停了等待时间不够，被误判成"没新内容"4.4
滚到底了，DOM 里还是没有后面的数据虚拟列表，只渲染可视区域4.5
数据重复了好几遍翻页时没换页 / 没清表4.6

4.1　症状一 · 抓早了

最容易被忽略的一种。表现是：同一个流程跑两次，导出的行数不一样（比如一次 20 行，一次 8 行）。

💡 诊断方法

连跑两遍，把两次的 CSV 行数记下来。不一样就一定是这个问题，不用再猜。

解法 · 在抓之前先等页面稳定

做法怎么配什么时候用
延迟拖一个「延迟」模块，填毫秒数（如 2000），放在抓取之前最快、最笨、但 80% 的情况够用
元素存在拖「元素存在」，选择器填"列表项"，把「尝试次数」调高想等一个具体的东西出现，而不是死等几秒
等待选择器在抓取模块上勾上⚠️ 只等第一个，列表场景基本没用（见 2.3）
📌 建议

新手直接在「获取文本」前面垫一个 2000 毫秒的延迟，先跑通再优化。盲调时间是野路子，但作为第一步非常有效。

4.2　症状二 · 只有第一页

练习站有 50 页。要抓完，有两条路，先看一眼哪个适合你的场景：

做法 A · 点下一页做法 B · 算页码
思路循环跑到没页可点为止1 到 50 挨个访问
靠什么模块「循环元素」+ 载入更多「循环数据」（数字）
适合不知道有几页、页码是乱的、无限滚动页码规则固定、页数明确
优点通用，不用猜页数可控、可中断、出错好定位
缺点慢；翻页有等待页数写死了，站点改版就失效

做法 B · 算页码（先学这个，可控）

循环数据数字 1 → 50→ 新建标签页page-{{loopData.page}}.html→ 获取文本 · 多选书名→ 获取文本 · 多选价格→ 循环断点↺
1

拖 「循环数据」，配置：

  • 循环 ID：page
  • 迭代数据来源：数字（Numbers）
  • 起始值 1 · 结束值 50

✓ 应该看到：设置栏里有起始值和结束值两个数字框

2

拖 「新建标签页」，URL 填：

https://books.toscrape.com/catalogue/page-{{loopData.page}}.html

✓ 应该看到：每轮打开的 URL 里页码在变

3

接上第 3 章那两个多选抓取模块（书名、价格），最后接 「循环断点」，循环 ID 同样填 page。

⚠️ 陷阱：先确认这个站的 URL 规则

练习站是 /catalogue/page-2.html，不是 /?page=2。

方法：手动打开第 2 页，看地址栏长什么样，照抄。每个站的翻页规则都不一样，不能套用。

⚠️ 陷阱：50 页 = 50 次开标签页，会很慢

每次开页都要等加载，全程可能要几分钟。调试时把结束值先设成 3 跑通，再放大。

4.3　症状三 · 滚到底才出数据

有些列表页只渲染首屏：往下滚，才加载接下来的内容。这叫懒加载或无限滚动。

解法就一个模块 —— 「循环元素」自带的"载入更多"功能。

1

把第 3 章那个 「循环元素」拿出来，在设置里找到三处新东西：

  • 载入更多动作 —— 五个选项：无 / 点击一个元素 / 向下滚动 / 点击一个链接 / 向上滚动
  • 载入更多元素 —— 选上面那个动作要点的元素
  • 滚动到底部 —— 勾上，每轮先把页面滚到底

✓ 应该看到：「载入更多动作」是一个下拉框，展开正好 5 项

2

对着练习站的分页按钮：

  • 载入更多动作 → 点击一个链接
  • 载入更多元素 → .pager li.next a
  • 滚动到底部 → 勾上
  • 最大循环数 → 0（不限，让它自己判断到没页为止）

✓ 应该看到：跑起来后日志里能看到页码一页页往下走

载入更多动作什么时候选它
无页面本来就一次全渲染出来了
点击一个元素有个「加载更多」按钮（不是真正的翻页）
向下滚动无限滚动，没有按钮，往下滚就出
点击一个链接有"下一页"链接，会整页跳转
向上滚动反向加载（往下滚会加载更早的内容）
📌 机械原理

它的工作方式是：每轮结束前，执行一次载入更多动作，然后重新扫描页面上匹配的元素，把新出现的追加到已有列表里。所以列表页的旧数据不会丢，理论上会越滚越长。

4.4　症状四 · 循环莫名其妙提前停了

这是"抓不全"里最隐蔽的一种：流程不报错、不提示、就是少了一大半数据，日志里也看不出异常。

先搞清楚循环是在什么条件下停的，才能对症下药。一共三条：

停止条件含义对应哪个开关
① 元素用完了已遍历的数量达到最初找到的数量—
② 达到上限跑够了「最大循环数」次最大循环数
③ 这一轮没等到新元素执行载入更多动作后，等啊等，超时了还没出现新东西等待更多元素的最长秒数
⚠️ 条件③ 是"抓不全"的头号原因

它的逻辑是："等不到新的，就认为到底了"。

所以如果你的站点慢 —— 点完"下一页"要 6 秒才渲染完，而「等待更多元素的最长秒数」默认只有 5 秒 —— 循环会在第 3 页就判定"没新内容了"然后安静地结束。

你不会看到任何报错，CSV 就是少了一大半。

解法

1

打开「循环元素」，把 「等待更多元素的最长秒数」 调大到 15；

再把 「等待页面加载完成的最长秒数」 调成 20。

✓ 应该看到：设置栏里有两个以"秒"为单位的数字框

2

把 「最大循环数」 设成你预期的页数（比如 50）。

💡 为什么建议"宁可设死"

设成 0（不限）意味着完全交给超时判断 —— 站点一慢就提前收工，而且你还不知道。

设成 50 意味着：抓够 50 轮就停，没抓够 50 轮也停，但你知道它没抓够。后者才是可排查的。

怎么确认到底是"抓够了"还是"提前停了"？

看日志里的最后一个循环轮次：

日志显示结论怎么办
跑满 50 轮才停✅ 抓全了没事了
只跑了 12 轮就停⚠️ 提前停了调大「等待更多元素的最长秒数」
第 49 轮停了最后一页了正常

4.5　症状五 · 虚拟列表（最难的一种）

有些网站为了流畅，只渲染当前看得见的那十几行，滚上去就销毁。这种叫虚拟列表。

⚠️ 识别特征

你手动滚到底、再滚回顶部，用 Alt+P 点一下，匹配到的元素数量永远只有 20~30 个，而不是全部 1000 个。

如果是这样，怎么写选择器都抓不全 —— 因为后面的数据根本不在页面里。

办法效果
「循环元素」+ 向下滚动 + 每元素等待能拿到一部分。边滚边抓，但滚太快仍会漏
降低滚动速度、加大等待时间缓解，但仍然不可靠
直接调它的数据接口✅ 唯一可靠的做法 → 见第 14 章
📌 怎么判断"能不能调接口"

在浏览器里按 F12 → 切到 Network（网络） → 筛选 Fetch/XHR → 滚动列表。

如果每次滚动都冒出一个返回 JSON 的请求 —— 恭喜，数据就在那儿，比爬 DOM 又快又全。

4.6　症状六 · 数据重复了好几遍

做完 4.2 的翻页流程后，你可能会发现 CSV 里有些书出现了好几次。

原因：表格是累积的。第 1 页写了 20 行，第 2 页又写了 20 行…… 而翻页时旧页面的数据其实还在 DOM 里，多选又把它们抓了一遍。

做法怎么配优缺点
翻页前清表翻页动作之前插一个「删除数据」，数据来自选表格简单，但清完只能留最后一页 —— 没用
每页先存变量，最后统一插入「循环数据」遍历的是变量，每轮把这一页的结果塞进变量，最后循环结束后一次性写入表格干净，但要多绕两个模块
用「点击一个链接」而不是开新标签页同 4.3 的做法推荐 —— 页面是整页替换的，不会重复
⚠️ 别用"清表"来去重

很多人第一反应是"每页前先清空表格"。这会把前面所有页的数据都清掉，最后只剩最后一页。越用越困惑。

正确做法是让页面自己换页（点下一页），或者用变量分段收集。

4.7　验证 · 怎么知道真的抓全了

抓完别急着收工。按顺序做这三件事：

1

对数 —— 页面底部写着"Page 1 of 50"，那 CSV 就该有 50 × 20 = 1000 行（去掉表头）。

✓ 差得多 → 回去看 4.4；差 1~2 行 → 正常，边界情况

2

连跑两遍比行数 —— 行数一样说明抓稳了；不一样说明还有 4.1 的问题。

3

看循环停在哪一轮 —— 打开日志，确认它是跑满预期轮次才停的，而不是中途放弃。

🎯 本章一句话总结

先对症状；抓到一半 → 等；只有第一页 → 翻页；循环提前停 → 调大等待秒数；DOM 里压根没有 → 去调接口。

5找不到元素时不出错

本章你会做什么：把第 4 章那个"能跑"的流程，改造成"跑十次都稳"的流程。
引入两个新概念：出错时 和 回退。

5.0　先分清三种"失败"

新手看到"失败"就慌，是因为把这三件完全不同的事混成一件：

失败类型样子危险吗
① 明着失败弹出红色报错，流程停住，日志里写着 element-not-found不危险 —— 你马上就知道了
② 跳过继续流程跑完了，但某一步是空的中等 —— 要主动去核对
③ 静默失败流程显示成功，但数据少了一大半最危险 —— 你完全不知道
⚠️ 本章最重要的一句话

流程没报错，不代表抓对了。第 4 章那个"循环提前停"就是典型的③ —— 绿勾，数据少 80%。

所以光加容错不够，5.7 节会讲怎么主动自检。

5.1　等待的三层防线

元素找不到，绝大多数时候是"它还没出现"，不是"它不存在"。所以要设三层：

第 1 层等待选择器→ 第 2 层模块超时→ 第 3 层出错时 · 重试
层在哪配配什么管什么
① 等待选择器模块设置里勾选选择器超时（毫秒）等元素出现。默认给 5000
② 模块超时模块设置里的「模块执行超时」毫秒，0 = 不限管住整个模块的耗时，防止它卡死
③ 出错时 · 重试模块设置里的「出错时」次数 + 间隔（秒）前两层都没救回来时，重来一遍
📌 怎么配

「等待选择器」勾上、超时 5000；「出错时」选重试操作，次数 2，间隔 3 秒。

这套是通用配置，几乎所有"网页交互"模块都该这么设。嫌麻烦就全选中了先跑一遍。

5.2　模块的「出错时」：四个动作

每个模块设置里都有一个「出错时」区域，展开后核心是这四个选择：

选项会发生什么
抛出错误流程在这里停住（默认行为）
继续流程跳过这一步，接着往下跑
执行回退从模块左侧接的那条线走 —— 这是分支的入口
重启流程整个工作流从头再来一遍

「出错时」里还能顺手做一件事：插入数据 —— 模块失败时，往表格里写一个标记值，比如"抓取失败"。

抓书名失败  →  表格里写入  书名 = "(未抓到)"  →  继续流程
💡 这一招很值钱

它把"静默失败"变成了"可见的失败"—— 导出的 CSV 里那行是空的还是写着"未抓到"，一眼就看出来，不用对数。

5.3　四种策略怎么选

这个元素……选什么为什么
偶尔抽风（网络抖动、渲染慢）重试操作 2~3 次重试能解决，就别改结构
本来就不一定有（比如"是否有货"）继续流程 + 插入数据标记没值是正常情况，不该算错
抓不到就整批没意义执行回退转到备用逻辑，或通知你
偶尔整个页面没加载出来重启流程从「新建标签页」重开一次往往就好了
不该发生，一旦发生就是 bug抛出错误（默认）让它停下来，别把脏数据写进表

5.4　「元素存在」：最该学会的健壮性骨架

前面讲的都是"出错了怎么办"。但更好的思路是先问一句"它在不在"，再决定要不要做后面的事。

「元素存在」这个模块就是干这个的，而且它有个默认行为很多人不知道：

💡 关键默认行为

「元素存在」默认不会报错。元素在 → 走上面那条线；元素不在 → 走下面那条线。

所以它天然是一个 if/else，不需要你再套一层「出错时」。

条件与控制流元素存在
.product_pod ──上（存在）──▶ 获取文本 · 多选书名 ──下（不存在）──▶ 通知"列表没加载出来"

配三个地方

1

拖 「元素存在」，元素选择器填 .product_pod。

✓ 应该看到：模块左侧有两条输出线，右侧有一条输入

2

把「尝试次数」调到 5，「超时」调到 1000 毫秒。

意思是：最多试 5 次，每次最多等 1 秒 —— 这样"等不到"最多浪费 5 秒，而不是干等 30 秒。

✓ 应该看到：这两个数字框决定了它愿意为这个元素花多久

3

别勾「如果不存在抛出一个错误」。留着不勾，它就老老实实走下面那条线。

📌 什么时候用「元素存在」而不是「出错时」

「元素存在」是主动问，用在流程开始时、每翻一页前、循环每轮开始时 —— 先确认环境对不对，再干活。

「出错时」是被动救，用在单个操作上。三层（5.1）+ 骨架（本节）一起上，流程就稳了。

5.5　实战 · 把第 4 章的流程改稳

5.6　流程级设置 · 整个工作流出错时

模块级的「出错时」管一个模块。工作流级的设置管全局，在工作流右上角「设置」里：

设置作用建议
工作流出错时三选一：继续运行 / 停止工作流 / 重启工作流停止工作流（默认最安全）
重新启动 · 次数选「重启工作流」时，最多重启几次1~2 次，别设成无限
工作流超时（毫秒）整个流程的时限抓整站建议 30 分钟以上

⚠️ 别把「工作流出错时」设成「继续运行」来"让流程跑完"

很多人流程跑到一半某页抓不到，选了「继续运行」想着"至少把后面的跑完"。结果是后面全是空行，你却以为成功了。

失败就该停。想让流程"知道自己没抓全"，用 5.7 的自检，而不是吞掉错误。

5.7　最危险的失败 · 静默跑完但数据不对

前面 6 节都在处理"流程挂掉"。但真正会坑到你的是流程没挂，数据却是错的。

解法只有一个思路：让流程自己数一遍，然后在数错的时候告诉你。

方法 · 用 {{$getLength(...)}} 数行数

Automa 内置了一个 $getLength 函数，能算出"某个列有多少行"。在流程末尾加一个「通知」模块：

本次抓取：{{$getLength(table.书名)}} 行，
价格缺失：{{$getLength(table.价格)}} 行
💡 为什么这有用

你不用再打开 CSV 数行数 —— 跑完自动弹一条通知告诉你抓了多少行。

两列数字不一样，说明有一列匹配失败或中途断了（回到 4.4 查）；数字明显偏小，说明循环提前停了。

1

拖 「通知」 接在「导出数据」之前（或之后都行），内容里写上面那行。

✓ 应该看到：跑完弹出一条系统通知，写着"本次抓取：20 行…"

2

如果浏览器通知权限没开，通知可能不弹。去工作流「设置」里确认「工作流通知」是开的，并在浏览器地址栏左侧允许通知。

给定时任务加一条底线

📌 一条建议

流程一旦设成每天自动跑，你就不在场了。请务必在末尾留一条「通知」，哪怕只是一句"跑完了"。

没有它的定时任务，等于一个坏了也不会告诉你的定时任务。

✅ 自检
🎯 本章一句话总结

三层等待（等待选择器 / 模块超时 / 重试）→ 存在性检查走双线 → 失败要看得见 → 末尾用 $getLength 数一遍行数。

6条件与分支

本章你会做什么：让流程"满足条件才做某事"，并且在第 3 章那个"价格 > 50"的占位上补上真的判断。
引入一个新概念：分支（一个模块走两条路）。

6.0　什么时候才需要分支

先泼一点冷水：新手最容易过度使用分支。判断越多，流程越难维护，也越难排查。

情况怎么做
每条数据都做同样的事不需要分支，直接做
只想要其中一部分用条件
元素可能抓不到用「元素存在」双线（见 5.4），不用条件
还没想到要判断什么先不做，等真的需要再加

6.1　「条件」：比一比

「条件」块干的事只有一件：比较两个值，然后从两条线里选一条走。

条件与控制流条件 ──上（真）──▶ 要做的事 A ──下（假）──▶ 要做的事 B

八种比较方式

运算符中文例子
=等于库存 = "In stock"
≠不等于类别 ≠ "Novel"
>大于价格 > 50
≥大于或等于评分 ≥ 4
<小于价格 < 20
≤小于或等于页码 ≤ 10
包含包含书名 包含 "Python"
数据存在数据存在上一模块的结果 不为空
⚠️ 比较数字前，先确认它真的是数字

第 3 章那个价格列，如果没加正则，存进去的是 £51.77。字符串不能比大小 —— £51.77 > 50 会永远判为假，而且不报错。

做数值比较前，务必先清洗成纯数字（第 10 章细讲）。

6.2　用「条件生成器」，别手写

「条件」块点开后有个条件生成器，左边选字段类型，右边选比较方式，中间填值。它支持这几类字段：

类别能选什么
值任意变量、表格列、模块上一轮的输出
元素元素文本 · 元素存在 · 元素不存在 · 元素可见 · 元素在屏幕内可见 / 隐藏 · 元素属性值
基础数据存在 · 变量已定义
数字 / 文本 / 布尔对应的字面量或表达式
💡 遇到"元素存在"型判断

直接在生成器里选「元素存在」，就不用另外拖「元素存在」块了 —— 少一个模块，流程更清爽。

但如果存在与否要走的分支不一样，还是用独立的「元素存在」块更清楚。

6.3　多个条件：AND / OR

点「添加条件」可以加第二个比较，默认是 AND（并且）：

价格 > 50  AND  库存 = "In stock"   →  两个都成立才走上线

可以在 AND / OR 之间切换：

组合含义什么时候用
AND全部成立才算真要同时满足多个要求（最常用）
OR有一个成立就算真满足任意一个就行
⚠️ 改完条件记得点「刷新条件连接」

在「条件」块设置里改完比较方式后，要点一下「刷新条件连接」，画布上的连线才会更新。否则你改了半天，连线还是老的。

6.4　实战 · 只抓贵的书

把第 3 章的循环流程改一下：

循环元素id=book→ 获取文本价格
正则 /£([\d.]+)/→ 条件价格 > 50 ──上──▶ 获取文本书名→ 插入数据写表格 循环断点id=book
1

拖 「条件」，用生成器配：左值选元素 → 元素文本，元素填 .price_color，比较选大于，值填 50。

✓ 应该看到：模块左边两条出线，右边一条入线

2

把书名抓取 + 插入数据接到上面那条线，循环断点接在最下面。

⚠️ 循环断点接哪里？

接在条件之后，不在条件的分支里。如果只接在上线上，那么"价格 ≤ 50"的轮次永远不会跳到下一轮 —— 循环会卡死或提前结束。

正确结构：条件 的两条线各自干完活，然后都汇合到循环断点。

3

跑一遍，看表格里是不是只剩 50 镑以上的书。

✓ 应该看到：20 本书里只留下价格 > 50 的那几本

📌 「条件」没有「出错时」

这是故意的 —— 条件块本身不会失败。所以"重试 / 抛出错误"那套对它不适用，别以为是自己漏配了。

✅ 自检
🎯 本章一句话总结

条件 = 比一比 + 走两条线。数字比较前先清洗；改完点刷新；循环断点接在分支汇合之后。

7四种循环，别选错

本章你会做什么：搞懂 Automa 三个循环模块的分工，从此不再纠结"该用哪个"。
这一章是辨析章，不教新操作。

7.0　先看这张表

模块什么时候用典型场景
循环数据我要遍历一份我给它的数据翻页 1→50、遍历变量、遍历表格、遍历导入的 CSV
循环元素我要遍历页面上的一批元素列表页一条条处理、加载更多
重复任务我要把同一段流程跑 N 遍连开 5 个标签、连点 3 次
While 循环我不知道要跑几遍，直到某个条件不成立重试直到成功、一直翻到没有下一页
💡 一句话区分

循环数据 = 数据驱动；循环元素 = 页面驱动；重复任务 = 次数驱动；While = 条件驱动。

7.1　循环数据 · 六种来源

「循环数据」的「依次通过」下拉框里有六个选项，这是它最强大也最容易懵的地方：

来源循环什么当前项怎么取
数字从起始值到结束值{{loopData.循环ID}}
变量一个已有的变量值{{loopData.循环ID}}
表格表格的每一行{{loopData.循环ID.列名}}
自定义数据你手写的 JSON{{loopData.循环ID.字段}}
Google Sheets在线表格的每一行{{loopData.循环ID.列名}}
元素（等价于循环元素）{{loopData.循环ID}}

最常用的两种配置

1

数字：依次通过选「数字」，「从数字」1、「到数字」50，循环 ID 填 page。

循环体里用 {{loopData.page}} 拿当前页码，{{loopData.page.$index}} 拿"第几轮"（从 0 开始）。

✓ 应该看到：设置栏里是一对"从数字 / 到数字"输入框

2

自定义数据：依次通过选「自定义数据」，在文本框里直接写 JSON：

[
  { "name": "北京", "code": "010" },
  { "name": "上海", "code": "021" },
  { "name": "广州", "code": "020" }
]

循环体里：{{loopData.city.name}}、{{loopData.city.code}}。

✓ 应该看到：预览区会显示"共 3 条"

⚠️ 别多写一层 .data

正确：{{loopData.city.name}}。写成 {{loopData.city.data.name}} 取不到值 —— 引擎会自动帮你补这一层。

7.2　重复任务 · 就是"跑 N 遍"

最简单的循环。只有两个字段：

  • 次数 —— 要重复几遍
  • 重复自 —— 从哪个模块开始重复（它自己不会被重复）

典型用法：

重复任务次数 5→ 新建标签页page-{{重复计数}}.html→ 获取文本 · 多选书名 循环断点↺
📌 重复任务也需要循环断点

是的，一样要接。和前两种循环的规则完全一致。

7.3　While 循环 · 跑到条件不成立为止

前三种循环次数都是事先知道的。While 是"不知道，先跑着看"。

它也配一个「当条件为 false 时执行」的出口线 —— 条件为假就退出循环。

While 循环条件：还有下一页 ──上（真，继续）──▶ 抓数据 + 翻页 ──下（假，退出）──▶ 导出数据
⚠️ While 最容易写出死循环

如果条件永远为真（比如"页面已加载"——加载完也还是真），循环就停不下来。Automa 检测到后会报 workflow-infinite-loop 强制停止。

写 While 的自检问题："什么情况下这个条件会变成假？" 答不上来就别用 While。

📌 什么时候循环元素就够了

如果你只是要"翻到最后一页"，循环元素 + 载入更多本身就会在没新元素时自动停（见 4.4）—— 不用额外套 While。

While 更适合跟数据/变量打交道的循环，比如"一直重试直到拿到接口返回"。

7.4　所有循环都一样的四条规则

不管用哪种循环，下面四件事完全一样。记这一节就够了：

规则说明
① 循环 ID 必须有循环块和循环断点上填同一个字符串。漏填或不匹配 → workflow-infinite-loop
② 一定要有循环断点循环体的末尾。不接 = 无限循环
③ 当前项用 {{}}不要多写 .data
④ $index 从 0 开始{{loopData.x.$index}} 是序号不是内容

7.5　循环可以套循环

这是完全合法的，而且很常用。最典型的结构：

循环数据（页码 1 → 50）
  └─ 新建标签页 page-{{循环值}}.html
       └─ 循环元素（.product_pod）
            └─ 抓详情页内容
            └─ 循环断点
  └─ 循环断点
⚠️ 嵌套时，循环 ID 不能重名

外层叫 page，内层就必须叫别的（比如 book）。两个都用 page 会互相覆盖，行为完全不可预期。

📌 越简单越好

新手常见的过度设计：把本可以用"多选"搞定的事，套了三层循环。先问一句"能不能不用循环"，答案往往是能。

✅ 自检
🎯 本章一句话总结

数据驱动用循环数据，页面驱动用循环元素，次数驱动用重复任务，条件驱动用 While。四个都配循环 ID + 循环断点。

8.0　表格是什么，什么时候才需要它

8.3　「额外行」· 一个被低估的功能

「获取文本」等模块里有个「添加额外的行」选项。勾上之后：

每次这个模块写入数据时，会先在表格里新建一行，然后往指定列填固定值，最后才写本模块抓的数据。

模块抓什么额外行
获取文本书名来源列写 books.toscrape
获取文本价格来源列写 books.toscrape
获取文本作者来源列写 books.toscrape

效果就是每一行都自动带上一个来源标记。

📌 什么时候用得上

一个流程抓多个网站/多个列表时，这个列能让你事后一眼看出每条数据是从哪来的，不用回头翻流程。

也可以用它加"抓取时间"、"页码"、"分类"这类固定信息。

⚠️ 额外行是"每次写入前"新建，不是"每次运行新建"

如果你的模块用了「多选」写 20 条，额外行会在这 20 条之前插一行，不是插 20 行。

9.0　最最最基础的一件事：把 A 的结果给 B

你在第 0 章已经无意识做过一次了 —— 在「获取文本」里填了 {{table.书名}}。那就是表达式。

规则只有一条：任何输入框里，{{ }} 包起来的内容都会被替换成真实值。

URL 里写   https://x.com?q={{table.书名}}
输入框里写 {{table.书名}}
搜索框里写 {{loopData.book}} h3 a
变量名里写   {{$date('YYYY')}}
⚠️ 缺一个数字就取不到值

{{table.书名}} 里，表名、列名必须完全一致（区分大小写）。写错不会报错，只是安静地变成空字符串。

结果：URL 变成 https://x.com?q=，然后页面 404，你会去查别的地方。

10数据清洗

本章你会做什么：把 £51.77 变成 51.77，把 1000 条书名按价格排序，导出干净的数据。

10.0　为什么抓下来的数据总要再洗一遍

网页上显示的是给人看的，不是给机器算的。三个典型症状：

抓到的东西问题怎么洗
£51.77带符号，不能排序求和正则剥掉符号（10.1）
star-rating Three要的是"3"，不是这串正则取中间（10.1）
A Light in the ...被截断了抓 title 属性（见工具页）

10.1　清洗的正则 · 在「获取文本」里直接做

最省事的清洗手段：「获取文本」模块自带正则框，抓完立刻处理，不用额外加模块。

目标原文正则结果
价格去符号£51.77/£([\d.]+)/51.77
取评分数字star-rating Three/star-rating (\w+)/Three
取价格整数部分51.77/\d+/51
去掉所有空格A Light /\s+/gALight
💡 正则怎么读

/£([\d.]+)/：斜杠是分隔符，£ 是字面量（英镑号），圆括号是"我要这一段"，[\d.]+ 是"一个或多个数字或小数点"。

只取括号里的是 90% 的需求 —— 记住"加括号"这一个动作就够了。

⚠️ 正则不匹配时会怎样

从源码行为看：匹配不上就原样返回原文，不报错。所以你看到一堆 £0.00 或者奇怪的字符串，多半是正则写错了 —— 去练习站对照一下原文长什么样。

10.2　「RegEx 变量」· 处理已有数据

数据已经抓完了才想清洗，用 「RegEx 变量」。它有两个方法：

方法干什么例子
匹配值取出匹配到的部分从"共 1000 条结果"里取出 1000
替换值把匹配到的换成别的把所有 "In stock" 换成 "有货"

还带三个标志开关：全局匹配（所有出现都处理）、忽略大小写、多行模式。

📌 标志怎么选

全局匹配不勾 → 只处理第一个匹配。这是"我只想改第一次"时的正确选择。
忽略大小写 → 处理 in stock / IN STOCK / In Stock。

10.3　「切片变量」· 掐头去尾

最简单的一个：给一个起（从）和止（到），取出中间那段。

变量值从到结果
共 1000 条结果141000
A Light in the Attic27Light
https://x.com/a/b/c015https://x.com/a
⚠️ 从 0 开始，不是从 1 开始

切片是程序的下标，第一个字符是 0。想要"从头到尾"就填 0 和一个很大的数。

10.4　「排序数据」· 按列排序

流程末尾插一个 「排序数据」：

  1. 根据属性排序数据项 → 填要排的列名（如 价格）
  2. 选 升序（从小到大）或降序（从大到小）
  3. 可以「添加属性」排第二、第三列（多级排序）

接在 「导出数据」之前，导出的就是排好序的。

⚠️ 按价格排序前，价格必须是数字

如果价格列是 £51.77 这种字符串，排序会按字典序来 —— £9.99 会排在 £51.77 后面（因为 "9" > "5"）。

排序结果看着"不对"但没报错，是最难查的一类问题。先回 10.1 清洗成纯数字。

10.5　实战 · 一条完整的清洗链

目标：把 books.toscrape.com 全站书名 + 纯数字价格，按价格从高到低导出。

①获取文本 · 多选
书名→ ②获取文本 · 多选
价格 · 正则 /£([\d.]+)/→ ③排序数据
价格 · 降序→ ④通知
{{$getLength(table.书名)}} 行→ ⑤导出数据 CSV
📌 注意「额外行」放在哪

如果你用了 8.3 的「额外行」加来源标记，它要在排序之前，否则排序会把标记行一起排乱。

💡 清洗的顺序

先正则（转成正确类型）→ 再切片/替换（修格式）→ 最后排序。
顺序反了会导致排序结果错误 —— 因为排序要建立在"类型正确"之上。

11.1　三个最常用的定时配置

① 每隔 N 分钟

类型选间隔，填间隔（分钟）和延迟（分钟）。

⚠️ 间隔 < 5 分钟不现实

浏览器扩展在标签页关闭时不会运行，系统休眠时也不跑。设成 1 分钟只会得到"有时候跑、有时候不跑"的错觉。

实用底线：至少 15 分钟，且要保证那个标签页开着。

② 每天固定时间

类型选在指定的星期 → 勾选星期一到星期五（或七天全勾）→ 填时间 08:00。

可以「添加时间」加多个点，比如 08:00 和 18:00。

✓ 应该看到：星期和时间点是可以分别添加的

③ 访问某网址时

类型选在网址时，URL 或正则表达式填：

https://intranet.example.com/reports*
⚠️ 这个类型容易和"新建标签页"打架

如果触发条件是"访问某网址"，那触发器本身就是执行入口，流程里不用再放「新建标签页」了 —— 页面已经在那了，直接开始抓。

多放一个不是错，但会多开一个标签页，反而让人困惑。

方式怎么做适合

发邮件 / 写在线表格「HTTP 请求」发邮件接口 / 「Google Sheets」模块真正想每天用的做法
📌 邮件怎么发

Automa 没有内置的发信模块。做法是用「HTTP 请求」调第三方服务（Resend / SendGrid / 自己的邮件网关），在 Body 里写 {{table.价格.0}} 这类表达式把数据填进去。

具体配置见 第 14 章。

触发器在指定的星期

  3. 工作流设置里打开「工作流通知」，并允许浏览器发通知。
📌 别忘了权限

13填表与登录

本章你会做什么：让流程自动登录某个网站，然后抓只有登录后才能看的数据。

13.0　先问一句：真的需要自动登录吗

登录是自动化的成本大头。在动手之前，先按这个顺序试：

顺序做法为什么先试它
①手动登录一次，让浏览器记住 Cookie最省事，很多网站够用几个月
②数据在接口里，带上 token 调最稳最快（见第 14 章）
③「表单」模块自动填 + 点登录通用，但脆弱（见 13.2）
④「Cookie」模块直接注入登录态需要手工取 Cookie，最难维护
💡 实践建议

定时任务最容易踩的坑是"登录态过期"。能用①②就别用③④。

13.1　「表单」模块 · 四种控件

「表单」模块管四种输入控件，用同一个模块搞定：

表单类型控件备注
文本域单行输入框、密码框、搜索框最常用
下拉列表<select>见下面的选项选择方式
单选框radio一组里只能选一个
复选框checkbox可以多选

三个会用到的小开关

开关什么时候开
清除表单值输入框里已经有内容，先清掉再填
输入延迟（毫秒）填完等一下 —— 很多网站要看到输入才触发联想/校验
选项选择方式下拉框选哪一项，见下

下拉框的四种选法

方式什么时候用
按值你知道选项的 value（最可靠）
按位置只想选第 N 个（比如"选第 3 项分类"）
第一个 / 最后一个省事，只关心首尾
自定义直接填要显示的文字
⚠️ 填完不生效？先加"输入延迟"

如果网站填完输入框要等一下才接受（联想搜索、React 受控组件、验证码），把输入延迟设成 300~800 毫秒。

这是表单模块最常见的失败原因。

13.2　自动登录的三种做法

做法 A · 手动登录一次（先试这个）

你手动登录，然后什么都不做，Automa 用的就是同一个浏览器的 Cookie。

适用：登录态能撑很久（几周~几个月）的网站。

做法 B · 自动填表 + 点击登录

新建标签页登录页→ 表单文本域 · 账号
{{secrets.账号}}→ 表单文本域 · 密码
{{secrets.密码}}→ 点击元素登录按钮→ 元素存在登录成功标志→ 继续抓数据

关键在最后那个 「元素存在」 —— 它是"登录到底成没成"的检查点。失败的那条线接一个「通知」。

做法 C · Cookie 注入

「Cookie」模块能直接读写浏览器的 Cookie。如果你能从开发者工具里拿到登录后的 Cookie 值：

  1. 目标站 F12 → Application → Cookies → 复制登录态字段
  2. 「Cookie」模块 → 设为 → 填域名和值
  3. 之后访问就带着登录态了
⚠️ Cookie 会过期

做法 C 最脆 —— 服务端会更新 Cookie，你抄的那份很快就失效，流程突然大面积失败。优先用 A 或 B。

13.3　凭据 · 别把密码写在流程里

把密码明文写在模块里，等于把密码存进了导出的 .json，分享流程时一起发出去。

正确做法是凭据：

  1. 主面板 → 存储 → 凭据 标签 → 添加凭据
  2. 填名字（如 books账号）和值
  3. 流程里用 {{secrets.books账号}} 引用
📌 凭据的三个特点
  • 只存在你自己的浏览器里，不随工作流文件导出
  • 在 JavaScript 代码块里拿不到 —— 引擎在注入上下文时会把凭据清空，这是刻意的安全设计
  • 编辑器里有「已用凭据」清单，方便你检查流程用了哪些
⚠️ 别在 JS 块里想要凭据

如果你写了 {{secrets.密码}} 在 JS 代码块里，它会拿到空值。

解法：在 JS 块外面先把凭据取到变量，再把变量传进 JS。

14调接口比抓页面快

本章你会做什么：跳过网页，直接从一个 JSON 接口取数据 —— 快十倍，而且不会被页面改版搞挂。

14.0　什么时候该调接口

前面 13 章都在抓网页 DOM。但很多时候，数据本来就在接口里，网页只是把它渲染成了好看的表格。

抓页面（DOM）调接口（HTTP）
速度慢（要加载整个页面）快很多
稳定性网站改版就挂接口不动就不挂
虚拟列表抓不到（见 4.5）完全没这个问题
要登录要处理 Cookie带个 token 就行
上手难度低要会看开发者工具
⚠️ 但也别一上来就调接口

接口调用涉及鉴权、参数、分页三件麻烦事。数据量小、页面结构简单时，抓 DOM 更快出结果。

建议：先用 DOM 跑通，碰到"抓不全"或"要登录"再换接口。

14.1　怎么找到接口

1

打开目标网页，按 F12，切到 Network（网络） 标签。

2

点顶部的 Fetch/XHR 筛选按钮 —— 这一类请求就是"网页自己偷偷取数据"的调用。

✓ 应该看到：列表里少了很多图片和 CSS，只剩 JSON 请求

3

滚动页面或点一下翻页，看有没有新请求冒出来。

✓ 应该看到：每次滚一下就多一个返回大段 JSON 的请求

4

点那个请求 → 看 Preview（预览），如果里面是你要的数组，复制 URL。

✓ 应该看到：一个长得像 https://.../api/products?limit=20&skip=0 的地址

💡 看不懂 URL 里的参数？

点请求的 Payload 标签，能看到它发了什么。Query String Parameters 那一栏就是 URL 里的参数含义。

很多接口靠 page / offset / limit 控制翻页 —— 看到 skip=20 就知道"每页 20 条，第 2 页 skip 20"。

14.2　「HTTP 请求」模块

它有四个区域：Headers（请求头）· Body（请求体）· 响应，加上顶部的请求方法和请求 URL。

字段填什么
请求方法GET（取数据）/ POST（提交）/ PUT / DELETE
请求 URL刚才复制的那个地址，可以写 {{ }} 表达式
Headers接口要认证时加 Authorization 等请求头
BodyPOST 时要发的数据
数据路径关键 —— 告诉它从响应的哪一层取数据
响应类型JSON / 文本 / Base64
💡「数据路径」是这一章唯一的新概念

接口返回的是一整块 JSON，但你只想要里面某个数组。数据路径就是用来指出"往里走几层"。

14.3　数据路径怎么写（JSONPath）

拿这个公开演示接口举例：https://dummyjson.com/products?limit=3，它返回的开头是：

{
  "products": [
    { "id": 1, "title": "Essence Mascara Lash Princess",
      "price": 9.99, "rating": 2.56,
      "dimensions": { "width": 15.14, "height": 13.08 } },
    ...
  ],
  "total": 194
}
数据路径取到什么说明
products整个商品数组最常用，先剥掉外层包装
products.title所有商品名数组里的每个对象的字段
products.dimensions.width所有宽度多层：一层层往里点
total总数 194不在数组里的顶层字段
💡 怎么配合循环用

数据路径填 products 拿到整个数组，直接喂给「循环数据」：

「HTTP 请求」 数据路径 = products  →  插到变量
「循环数据」 依次通过 = 变量  循环 ID = p
循环体里：  {{loopData.p.title}}   {{loopData.p.price}}

14.4　实战 · 翻页调接口

循环数据数字 0 → 9
skip = 轮次 × 20→ HTTP 请求GET products
路径 = products→ 循环数据遍历返回的数组→ 插入数据title / price→ 循环断点×2
⚠️ HTTP 请求没有「出错时」

它自带一条「在发出 HTTP 请求失败或错误时执行」的线。接口报错时走那条线，别去模块里找"出错时"——找不到不是你的问题。

📌 什么时候停止翻页

用返回里的 total 或 products 的长度判断。用「条件」比一下就知道该不该停（见第 6 章）。

14.5　什么时候必须用接口

情况只能用接口
虚拟列表（DOM 里只有 20 个节点）✅
要登录才能看的数据✅ 带 token
数据要几千上万条✅ 快很多
网页结构复杂、选择器难写✅ 常常是
只要页面上显示的那几个字段抓 DOM 就够

15结果去哪

本章你会做什么：把数据送到真正要用它的地方 —— 文件、在线表格、邮件。

15.0　先说一个常见误解

⚠️ 导出格式只有三种

JSON / CSV / 纯文本。没有 .xlsx（Excel）格式。

要 Excel 就导 CSV 再用 Excel 打开。务必勾上「添加 UTF-8 BOM」，否则 Excel 打开中文列名会乱码。

格式选它的时候
CSV要给人看 / 给 Excel / 给 pandas —— 日常 90%
JSON要喂给别的程序；或者数据里有嵌套结构（CSV 存不了）
纯文本只要一串文字，比如把摘要拼成一句话

15.1　「导出数据」的四个设置

设置说明
要导出的数据表格 / 变量 / Google Sheets —— 不选的话默认导表格
导出为CSV / JSON / 纯文本
文件名不写扩展名，Automa 自动加
添加 UTF-8 BOMCSV 场景建议一直勾（默认就是开的）
分隔符CSV 专用，默认逗号；数据里本身有逗号时改成制表符或分号
⚠️ 文件已存在时怎么办

「导出数据」有个文件冲突设置：唯一 / 覆盖 / 询问。

定时任务务必用"唯一"（默认）—— 否则第二次跑会覆盖第一次，你以为在累积，其实只剩最后一次。

⚠️ 数据里有逗号 / 换行

CSV 用逗号分隔，如果某个书名里本身有逗号，Excel 可能对错列。

解法：把分隔符改成分号 ; 或制表符。Autooma 会对内容做转义，但改分隔符更保险。

15.2　Google Sheets · 不用下载就能看

不想每天去翻下载目录？把结果直接写进在线表格。

「Google Sheets」模块需要先在主面板的设置里连接 Google 账号。配好后：

  1. 拖 「Google Sheets」模块，动作选更新/追加
  2. 选表格 id 和工作表名（范围可选）
  3. 在末尾再拖一个 「导出数据」，导出为选 Google Sheets —— 这样表格列能自动对上列名
📌 什么时候值得用

多人协作看结果、定时任务不适合下载到本地、或者想在手机上随时看 —— 这三种情况在线表格明显更合适。

15.3　发邮件 / 推送到别处

Automa 没有内置发信模块。做法是用「HTTP 请求」调第三方服务的接口：

想做什么怎么做
发邮件「HTTP 请求」POST 到 Resend / SendGrid / 自己的邮件网关，Body 里写 {{table.书名.0}} 这类表达式
发到微信/钉钉/Telegram这些都有"机器人 webhook"，POST 过去就行
推给自己的系统POST 到自己的 API
只想知道跑完了「通知」模块，最省事
💡 邮件正文怎么填数据

Body 里直接写表达式，发送前会被替换成真实值：

今日抓取 {{$getLength(table.书名)}} 本书，
最贵的一本是《{{table.书名.0}}》，£{{table.价格.0}}

（这里假设表格已按价格降序排好，第 0 行就是最贵的。）

15.4　选哪个？

场景方案
自己跑一次看看导出 CSV
每天跑，要留档导出 CSV（文件名带上日期：books-{{$date('YYYY-MM-DD')}}）
团队要看 / 手机要看Google Sheets
要立刻知道结果通知 / 机器人 webhook
喂给别的系统导出 JSON 或 POST 过去
⚠️ 定时任务 + 文件名 = 最容易忘的坑

每天跑都叫 books.csv，加上默认"唯一"策略，你会得到 books (1).csv、books (2).csv… 堆一整个下载目录。

文件名里加日期：books-{{$date('YYYY-MM-DD')}}。一次解决留档和堆积两个问题。

本章你会做什么：把一段常用的流程打包，以后一句话调用，而不是复制粘贴。

16.0　什么时候该复用

信号很明显：你开始复制粘贴同一段模块了。比如你有三个流程都要"登录 → 开列表页 → 导出"。

方法怎么用适合
① 右键 → 副本最土但最快的办法临时改一点点的场景
② 保存到文件夹把选中的模块存成模块文件夹里的一个积木个人最常用
③ 执行工作流调用另一条完整流程流程之间要传参、要返回结果
④ 模块包打包成带输入/输出的黑盒，可分享要分享给别人用

16.1　保存到文件夹 · 最快的复用

1

框选要复用的那几个模块 → 右键 → 「保存到文件夹」。

✓ 应该看到：左侧模块面板多出一个模块文件夹分组

2

下次要用，展开模块文件夹，直接把那一组拖进画布。

✓ 应该看到：一整组模块连带内部连线一起出现

📌 它和"分组模块"的区别

分组模块只是把模块圈起来方便整理（还方便整组一起禁用/复制）；保存到文件夹是存起来下次能直接拖出来用。

16.2　执行工作流 · 流程调流程

「执行工作流」模块可以调用另一条独立的工作流。这比模块文件夹强在两件事：能传参、能用参数提示收输入。

主流程循环数据 5 个关键词→ 执行工作流子流程-搜索
关键词 = {{loopData.kw}}→ 回到主流程继续下一轮
1

子流程里加一个 「参数提示」模块，定义要接收的输入（如 关键词）。

2

主流程里拖 「执行工作流」，选那条子流程，插入当前工作流变量把值传过去。

✓ 应该看到：子流程被调用 5 次，每次拿到不同的关键词

⚠️ 注意「覆盖全局数据」

「执行工作流」有个提示：这会覆盖所选工作流的全局数据。子流程如果用到全局数据（GlobalData），要注意别把主流程的冲掉。

📌 拆多细？

经验值：有独立价值、可能单独复用的部分才拆成子流程。为了"看起来整齐"而拆，只会让调试变难。

场景例子

17.1　一个能跑的最小例子

拖一个 「JavaScript 代码」模块，默认内容是：

console.log("Hello world!");
automaNextBlock()
⚠️ automaNextBlock() 是必须的

没有这一行，流程会卡在这个块不走。

（好消息：如果你自己没写，Automa 会自动帮你补上。但显式写出来更清楚 —— 尤其当你有 return 或 await 的时候。）

换成实用的：把当前页面的所有链接抓出来，传给下一个模块。

const links = [...document.querySelectorAll('a')]
  .map(a => a.href)
  .filter(h => h.includes('catalogue'));

automaNextBlock(links);   // 把数组传给下一个模块
1

在「执行上下文」里选 当前标签页（website）。

✓ 应该看到：一个下拉框，选项是"当前标签页 / 背景"

2

粘贴代码，点运行，确认没报错。

✓ 应该看到：日志里打印出抓到的链接数量

17.2　两个执行上下文

上下文能不能碰网页用在哪
当前标签页能，document 可用操作页面元素、读 DOM
背景不能做纯计算、拼数据
⚠️ 在「背景」里写 document.querySelector 一定失败

背景上下文是扩展自己的后台页，没有你要抓的那个网页。这类错误很常见，报错信息也往往不够直白。

17.3　三个容易踩的坑

坑症状解法
忘写 automaNextBlock()流程卡住不动补上；或者依赖自动补全
拿不到凭据{{secrets.x}} 是空的引擎会清空 JS 上下文里的凭据，在块外面先取到变量
用 return 想传值下一个模块拿不到用 automaNextBlock(值)，不是 return
