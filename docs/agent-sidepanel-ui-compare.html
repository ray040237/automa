05值得借鉴的清单

按「价值 × 落地成本」排三档。每条都给了来源文件与它解决的真实问题 —— 没有问题的设计不值得抄。

高

语义化圆角三级 token：chip / control / card

把现在按手感挑的 rounded-lg / rounded / rounded-md 换成有名字的三档，每个组件按「它是 chip、是控件、还是卡片」选，不再靠记忆。

为什么：现在同一个面板里 4px / 6px / 8px 并存，新加组件时无从判断该用哪个；且 Tailwind 默认 rounded-sm/md/lg 与项目既有用法会互相漂移 —— pie 特意用了 chip/control/card 这种不与默认刻度重名的名字，就是为了避免这个。

来源 pie-ai-agent/src/sidepanel/index.css:197-232（@theme）· 落地成本：低，改 config 加三个 borderRadius 即可，无需动组件

高

统一缓动曲线 + 时长 token + reduced-motion 兜底

先定死一条曲线（cubic-bezier(.32,.72,0,1)）和三档时长（140 / 200 / 260ms），再谈"加什么动画"。同时补一条全局 prefers-reduced-motion 压制规则。

为什么：Automa 面板现在只有 5 处零散 transition，没有公共语言。要补消息入场、视图切换这类动画时，先有曲线和时长 token，动画才不会各自发明参数。reduced-motion 是无障碍硬要求，顺便一起落。

来源 index.css:294-366 + components/ui/motion.tsx（DURATION 秒制镜像）· 落地成本：低，纯 CSS

高

HITL 卡片按「作用域」双色分档

确认卡按触及本机执行（local）还是只在浏览器域内（browser）分两种配色：local 走 warning 暖色，browser 走 accent 冷色；主按钮是卡里唯一浓色块，卡体保持中性 surface。

为什么：这条与本项目 ADR 0002 的工具分级高度同源 —— 你们已经按 read/write 分了确认门，但卡片视觉上还没把这个分级说给用户。用颜色回答"这步会碰到我电脑吗"，比读文案快得多。

来源 components/hitl/HitlCardShell.tsx:8-17 · 落地成本：中，需与 ADR 0002 的 class 定义对齐后改 AgentConfirmCard.vue

中

富文本复制（同时写 text/html 与纯文本）

复制助手回复时把 innerHTML 一起写进剪贴板，粘贴到 Word / Notion / 飞书能保住粗体、列表、标题、表格；hover 时高亮"将被复制的范围"。

为什么：Automa 现在的「复制全文」只给纯文本，表格粘出去就散了。而助手最常见的产出恰恰是表格和结构化列表 —— 这是用户真会遇到的痛，不是锦上添花。

来源 components/copy-rich-text.ts + Chat.tsx:1795-1821 · 落地成本：低，AgentMarkdown.vue 里已有复制按钮，换实现即可

中

两段式停止保护

首次按 Esc / 点停止，只进入 armed 态（按钮变 warning 色 + 外发光 + 文案变「再按一次停止」），2 秒内二次确认才真的 abort。

为什么：Automa 的停止与发送共用同一个按钮位，忙碌时一发即停 —— 误杀一个跑了半分钟的任务代价很高。这条直接补在现有按钮位上，不占新空间。

来源 Chat.tsx:219-251 · 落地成本：低

中

Composer 顶部渐隐替代硬分割线

在输入区上方放一条 -top-5 h-5 的 from-canvas to-transparent 渐隐层，消息滚到输入区下方时"溶解"而不是被切线切断。

为什么：Automa 的 composer 是一条实边框卡片（T-166 才合并成一框），消息流在边界处是硬切。渐隐能让"下面还有内容"这件事自然浮现，成本只有一个绝对定位 div。

来源 Chat.tsx:2003 · 落地成本：低

中

用户长文本自动折叠 + 底部渐隐

超过 240px 的用户消息自动折叠，底部渐隐 + "展开/收起"；全面板统一 [overflow-wrap:anywhere] 防长 URL / base64 撑破面板。

为什么：Automa 已经用 overflow-wrap:anywhere 解决了撑破问题（AgentToolStep.vue:42-51 有注释），但用户气泡还没折叠 —— 侧栏 360px 宽，一条长提问能把一屏占满。

来源 components/CollapsibleText.tsx（COLLAPSED_MAX_PX=240）· 落地成本：低

中

「AGENT 表头每轮只出一次」

一次用户提问后的第一条助手消息带表头（图标 + 徽标），同轮后续 loop 产出直接续流，不再一段段起头。

为什么：agent loop 一轮会产出 thinking → 多个 tool → 最终回复，每段都起头会让消息流碎片化。Automa 用的是 slot 体系（fold.js），落地前要先确认 slot 与"轮"的对应关系，不是直接抄。

来源 Chat.tsx:689-702 · 落地成本：中，需先理清 fold.js 的 turn 语义

中

上下文环形图的口径注释

环心不只显示百分比，还显示缓存命中率；分子用 lastPromptTotalTokens ?? lastInputTokens。

为什么：这条的价值在注释里 —— pie 明确记录了 Anthropic 系 provider 的 input_tokens 不含 cache_read，直接算会严重低估水位。Automa 已有 AgentContextRing.vue，值得把这个陷阱写进自己的注释。

来源 components/ContextRing.tsx · 落地成本：低（只补注释与口径判断）

低

窄面板 Markdown 三项预处理

① 剥掉围栏外的 4 空格缩进（防 LLM 输出意外变代码块）；② 转义货币符号（$3.5B 不被当公式）；③ 规范 \(..\) → $..$。

为什么：Automa 没有数学渲染，②③ 不适用；① 值得拿 —— 助手经常吐带缩进的 YAML/JSON，被误判成代码块是真实发生过的烦人事。

来源 components/Markdown.tsx（stripIncidentalIndentedCode）· 落地成本：低，agent/markdown.js 里加一道预处理

低

会话列表按状态分区 + 底部存储占用条

active / paused / failed / archived 四态分区（当前会话左侧 2px accent 竖条），归档可折叠，底部一条 STORAGE · N.N MB。

为什么：Automa 按天分组是时间视角，pie 按状态是任务视角。对"跑了一半的会话"后者更好用 —— 但 Automa 的会话是持久化在库里的，是否要引入 paused/failed 态是产品决策，不建议只为了 UI 改数据模型。

来源 SessionDrawer.tsx + SessionRow.tsx · 落地成本：高（牵扯会话状态模型）

06不建议照搬的部分

这些看着好看，但搬到 Automa 会水土不服 —— 有的依赖技术栈，有的依赖宿主，有的只是别人的品牌资产。

照搬前先想清楚

  • 引入 framer-motion / motion —— 那是 React 库。Vue 侧要么用 <Transition>，要么纯 CSS keyframes。为了几个入场动画拉一个动画库不划算。
  • Tailwind v4 CSS-first 的 @theme 体系 —— Automa 是 v3 + tailwind.config.js，@theme 语法不存在。可以搬它的 token 命名与取值，不能搬写法。
  • PieFace IP 形象状态机（wake/idle/listening/thinking/working/success + 十来个 keyframes）—— 那是品牌资产，不是通用交互模式。Automa 用 Remix Icon 的 spin 表达忙碌已经够用，换成一个会呼吸的脸反而稀释品牌。
  • dot-grid 点阵底纹 —— 铺在根容器上的 24px 网格。它是 pie 视觉语言的一部分，Automa 的中性面板没有这套语言，单独加一层底纹会显得来历不明。
  • 图片渲染 / KaTeX 数学公式 —— Automa 刻意把图片降级成 alt 文本（markdown.js:112-114，注释：外链图不可控、不该自动发起请求）。这是有依据的安全取舍，不要为了"功能更全"推翻它。
  • 会话 paused / failed / archived 状态机 —— 见上一节最后一条，那是数据模型改动，不是 UI 改动。
  • 面板宽度完全交给浏览器 —— pie 只有一个宿主所以能这么做；Automa 要同时应付编辑器侧栏（下限 360px 可拖宽）和独立助手页，host.layout 分轴是更对的答案，别简化掉。
