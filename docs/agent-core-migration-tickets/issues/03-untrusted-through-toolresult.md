## 完成记录（2026-10-05）

包装点定在**适配层**（`tools/adapter.js`），与产出内容同处 —— 拆成两处就多一个能拆错的地方。`loop.js` 只把 `wrapUntrusted` 注入进去。

`wrapUntrusted` 在 `toToolResult` 与 `toAgentTools` 两处都是**必填**，缺则抛。这顺手把 T-55 彻底做完了：现在没有任何路径能拿到「不逃逸的兜底」。

新增 8 条测试钉红线第 2 条，其中三条是「不通过就意味着防护失效」的那种：

- 包装必须是**单个**内容块（pi 会用换行拼接多块，拆分点落在标签内就断标签）
- 超长值截断后闭合标签仍在（截断在包装之前）
- 内容里的伪造闭合标签被中和（全文只允许一个真闭合标签）
- 工具抛错的路径同样走包装（否则错误消息成了一条可信通道）
- 页面组用 `page_content`、其余用 `tool_result`
- 用到的标签都在已登记清单里（未登记 = 逃逸清洗不认 = 防护形同虚设）

### 踩到的一个 bug（值得记）

`wrapObservation` 的**错误分支读 `outcome.message`，成功分支读 `outcome.payload`**。我先传了 `payload`，结果错误原因全变成「未知原因」—— 而这不会报错，模型只会看到一句没信息量的观察值。

已改成按成功/失败分别构造入参，并在代码注释里写明这个键名差异。
