**Status:** ✅ 已完成（2026-10-05）—— 全量 **371 tests / 348 pass / 0 fail / 23 skipped**

**What to build:** 用户发一条消息，助手流式回答一句话，过程中 UI 能看到思考、文本增量、目标页行与收尾——**不涉及任何工具调用**。这是整个迁移的第一条 tracer bullet：证明 pi 的内核能在浏览器扩展里加载、驱动、并且能把它的原生事件映射成我们的 10 种 agent 事件。

### 实测发现的三个行为（写给后续票）

1. **pi 会为 user 消息也发一对 `message_start` / `message_end`。** 映射层必须按 `message.role !== 'assistant'` 过滤，否则 UI 会把用户自己说的话显示成助手发言。已加测试钉住。
2. **文本增量被拆成多个 `text_delta` 事件**，不再是「一个 chunk 一整段」。任何断言「某条 TEXT_DELTA 等于全文」的写法都会失效——要拼起来比对。
3. **pi 的流事件形状没有强制要求。** 实测四种形态（缺 `partial` / 缺 `result()` / 两者都有 / 真 `AssistantMessageEventStream`）跑出来结果完全一样。所以「缺 partial 导致文本增量消失」「缺 result() 导致 `response.result is not a function`」这两条**不成立**，别照着传。夹具带 `partial` 与 `result()` 只是为了贴近生产形状。

### 两处必须保持的行为契约

- **出错收尾发 ERROR、不发 DONE**，且 `send` 返回 ERROR 事件。UI 靠「有没有 DONE」区分正常收尾与出错收尾（现状行为）。
- **用量取最后一条 assistant 消息**，不是最后一条消息 —— 因为第 1 条那个行为，transcript 末条不一定是 assistant。

### 没做的

**打包验证没做** —— 验收标准里的「产物体积差值」留到票 05，因为 `index.js` 的装配层接线要等provider 层就位才能真正跑通打包。现在打包只会失败在一个已知未接的地方。
