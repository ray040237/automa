## 三条要特别小心的

**#30（悬空 tool_calls 净化）是 B7 欠账的前提。**它现在测的是 `wire.js` 的净化逻辑；换pi 后由 provider 层负责（更完善：会插入合成结果）。**这条测试不能删**，要改成断言 pi 侧的等价行为 —— 否则 B7 将来做「上一轮被中断」的提示时没有安全前提。

**#37（日志打点）容易在重构里被整体丢掉。** 断言里写死了打点名，但这些名字是我们自己定的，pi 不管。重构时至少要保住「工具调用与结果有打点、参数摘要能看出模型传了什么」。

**#26（半截 JSON）夹具要改，断言不要改。** 它现在用手写假 chunk 当夹具，而第25 条的注释明确说过这个教训：「夹具按消费方写的形状，生产方根本不产出那个形状」。改成 pi 之后要问：**pi 产出的形状和手写夹具一样吗？** 不一样就必须换成真实的 pi 夹具，否则就是重犯第 25 条记录的那个错。

## 停损点用法

重构过程中若出现「说不清是重构引入还是本来就有的问题」，查这张表：

- 该条在「契约」里 → 旧实现下是过的，现在不过，**是重构引入的**
- 该条在「实现」里 → 旧实现下测的是内部细节，现在函数没了，**不是 bug**
- 该条在「随票走」里 → 属于后续票的范围，**现在不过不算回归**
