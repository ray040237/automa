Agent 工具卡设计稿 · 窄形态溢出与体量收敛

窄宿主（编辑器 320px 侧栏）下展开工具卡时，观察值里的长无空格串（ file:///…、https://…、长 tabId）会把卡片横向撑破， 正文区出现左右滚动条；同时展开体量过大（max-h-80=320px，超过面板一半）。 本稿给出四条规则，在不改变“工具卡紧凑、可与思考/通知卡区分”的前提下收敛。

两边都是 320px 侧栏；展开态，观察值内容相同。

二、根因（为什么 break-words 没兜住）

  • 卡片是 shrink-to-fit。 工具卡在 transcript 的 flex 列里带 self-start（保持紧凑、不拉满整行）。非 stretch 的 flex 子项按 fit-content 定宽，而 fit-content 的下界是内容的 min-content。
  • overflow-wrap: break-word 不参与 min-content。 它只在“行盒排不下”时断行，不会把一个长串的 min-content 宽度变小。 于是长路径/URL 的 min-content > 320px 面板 → 卡片被撑到 min-content 宽 → 溢出。
  • overflow-x-auto 兜的是叶子，不是容器。 当被撑宽的是 容器本身时，叶子上的横向滚动条救不了 —— 外层 flex 列直接横向溢出。
  • 体量。 折叠行 py-2、展开体 max-h-80(320px)， 在约 540px 的面板里占去一半以上。

三、方案：四条规则

① 卡片永不比面板宽 —— max-w-full min-w-0
给工具卡根节点上保险：即使内容再长，卡片宽度也被夹在 100% 以内， min-w-0 解除 flex 子项默认的 min-content 下界。
② 长串就地折断 —— overflow-wrap: anywhere
与 break-word 的关键差别：anywhere 参与 min-content 计算，所以容器不再被长串撑宽；正常文本仍优先在词边界换行， 只有“一个词长过一行”时才在任意处折断。这是本问题的正解， break-all（任意字符都断）会破坏可读性，是次选。
③ 展开体只允许纵向滚动 —— overflow-y-auto
去掉 overflow-auto / overflow-x-auto： 横向溢出必须靠 断行 解决，而不是靠滚动条 —— 滚动条只是把 “看不见的内容”藏起来，窄形态下反而更糟。纵向保留滚动，超长观察值仍可看全。
④ 体量收敛
折叠行 py-2 → py-1.5（每张省 4px）； 展开体 max-h-80(320px) → max-h-56(224px)。 工具卡仍然保留 self-start 的紧凑形态，与思考卡（全边框+左箭头）、 通知卡（左竖线）继续可区分。

同型长串隐患一并收口

用户气泡（whitespace-pre-wrap 无断行规则）与错误卡正文 （break-words 不收缩 min-content）会遇到同一类长串溢出。 统一加 [overflow-wrap:anywhere]，让“窄形态下长串不溢出”成为 聊天区的一条统一约束，而不是工具卡的单点补丁。

四、不改什么

  • 保留 self-start。 工具卡继续紧凑（内容短时不拉满整行）， 本稿只让它“短则紧凑、长则换行、永不超过面板”。
  • 不动状态色与图标。 绿/红/琥珀与 ✓/✕/⊗ 的语义（T-13、T-172）不变。
  • 不动展开交互。 仍是按钮 + aria-expanded，点击展开/收起。

五、顺带修正（同一轮复查出来的）

改完工具卡，按“每改必补守卫”的纪律重建 + 跑全量测试时， cssSpecificity 守卫（T-171）报出一条既有冲突，与工具卡无关但同源：

  • composer 输入框的 rounded-none 没带 ! —— 与同一元素上已有的 !bg-transparent !px-1 !py-1 不一致。 已统一为 !rounded-none（守卫推荐的“加 ! 前缀”手法）， 不再依赖 border-radius 工具类的产出顺序。
  • 守卫方向本身存疑（仅记录，本次未改）。 该守卫判据是 at(passed) > at(base)，即把“调用方排得更靠后”当成“输”； 但 CSS 同优先级下后来者赢，方向恰好相反 —— 本次实测 .rounded-lg 在 .rounded-none 之前， 后者实际获胜。把方向反过来会当场暴露两处真实既有 bug： TriggerElementOptions.vue 与 EditorLocalActions.vue 里 <ui-input class="block"> 被组件自带的 inline-block 吃掉。是否修守卫与这两处，另立一项。
