窄形态的历史是整块替换正文区（view: chat ↔ history）， 不是横向常驻栏。侧边栏宽度下这正是唯一可行且够用的形态 —— 列表项一行一条， 不挤。

为什么不能保留「宽形态」？
宽形态靠的是「240px 常驻列表 + 对话区横向并排」。放进侧边栏：

  • 320px 侧栏 → 列表 240 + 对话 80px，对话区被压成一条，不可读；
  • 400px 侧栏 → 列表 240 + 对话 160px，仍然濒临不可用；
  • 而 chrome.sidePanel 宽度不可由扩展控制（官方 issue #1011 明说 not supported）， 用户可能永远停在 320px。

所以迁移的前提就是放弃 wide，全面改用 narrow。好消息是 AgentPanel.vue 早已同时支持两种形态，删掉 v-if="wide" 那条左栏分支即可，不需要重写面板。

侧边栏相比主面板标签页，真正赢在哪：

场景 主面板标签页（现状） 浏览器侧边栏（迁移后）
看网页时问助手 切走标签页 → 问 → 切回 原地，网页与助手同屏
切到另一个网页继续问 助手页在别的标签，看不到新页 侧栏常驻，跨标签页存活
对比两个页面 做不到（助手跟着主面板） 来回切标签，助手跟着变
需要展开工作区 宽屏可拖大到全宽 受限于 ~400px

④ 结论：这条判断成立吗

问题demo 结论
窄 UI 与侧边栏 UI 能否大致相同？ 能。320–400px 区间内是同一套布局，无分叉点。
是否必须放弃 wide 形态？ 必须。240px 常驻栏在 ≤400px 内不可行，且宽度不可控。
面板组件是否要重写？ 不要。删 v-if="wide" 左栏分支 + 接线换 layout 即可。
还缺什么信息才能拍板？ 真机实测两件事：
① 侧栏在 chrome.sidePanel 里的真实默认宽度（320 还是别的数）；
② Firefox sidebar_action 是否接受同一套页面。
