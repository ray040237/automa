§0 结论（v2）

  • 三态统一为「图标 + 标题 + 徽标」同一个骨架，徽标是三态的"状态灯"：
    状态徽标样式可交互
    自动（默认）跟随灰描边（line 边 + fg-3 字），最轻否（只显示）
    已固定已固定 ✕accent/15 实底，hover 转 danger 红是（点击 = 解除）
    失效已关闭 / 已跳转danger/15 红底红字否（chip 本身可点 = 重选）
    三个徽标长在同一个位置、同一套圆角字号，只有颜色深浅和可点性不同 —— 视觉连续谱替代 v1 的"有没有徽标"。
  • 徽标内不放状态图标（v2 修订）：⚡ 撤掉。三个徽标已有三重区分（颜色深浅 / 文案 / 可点性），10.5px 的小胶囊里再塞图标只有拥挤没有信息。唯一例外是固定态的 ✕ —— 它不是状态图标，是"这个徽标能点"的动作线索，且只在可点的那个徽标上出现。
  • 解除动作只有一条路：点固定态徽标。下拉 = 纯标签页清单（选某页 = 固定），不再有「跟随当前页」行。
  • 失效态去掉「重新选择」文字：红徽标已经把话说完，chip 本身点开就是列表 —— 重选路径本来就在，行内 CTA 是同一个动作的第二张脸。
  • ✓ 语义统一：下拉里 ✓ 永远标在「助手此刻正在读的那一行」—— 自动态时它落在解析出的当前页上，固定态时落在被固定的页上。永不多于一个。
  • 「窗口 N」组标照 v1 撤：节标改「标签页 · N」（12px 中字重）；单窗口不分组；多窗口窗口号降级为行内右缀小徽标。

§1 现状问题（不变，v1 §1-§2 的分析仍成立）

固定态右侧三个同形状信号（徽标不可点 / ✕ hover 解除 / 箭头 hover 开列表）打架；解除后 chip 失去边框、徽标、实底，看起来像"没了目标页"；失效态的「重新选择」与"点 chip 开列表"是同一动作的两个入口。

§3 目标态：三态渲染（v2）

① 自动态 · light（默认）

跟随

徽标「跟随」说状态，标题说"跟的是哪页"——两者分工。徽标无 hover、无 pointer，纯指示。

② 固定态 · light（徽标可点 = 解除）

徽标 hover 整块转 danger 红 = 解除确认色。chip 主体（图标+标题）仍是开列表的 trigger。

③ 失效态 · light（只提示，CTA 撤）

已关闭

「重新选择」撤掉 —— chip 点开就是列表，重选路径不变，少一个同义入口。

① 自动态 · dark

跟随

② 固定态 · dark（hover 徽标转红）

③ 失效态 · dark

已跳转

§4 状态流（v2 简化）

⚡ 跟随（默认）
徽标灰描边、只显示 ── 下拉点选某页 ──▶ 「已固定 ✕」
徽标可点 ── 点徽标 ──▶ 跟回
+ toast（§7 唯一待拍板）
  • 固定：下拉点选，唯一来源（显式动作才固定，T-164 理由不变）。
  • 解除：点固定态徽标，唯一路径 —— 没有第二条路，也就没有"两个入口打架"。
  • 重选：失效态直接点 chip —— 路径本来就在，行内 CTA 撤掉。

§5 下拉（v2：无「跟随」行，✓ = 当前读的来源）

目标态 · 单窗口（节标「标签页 · 3」，无组标）

标签页 · 3

✓ 落在「Z.ai」行 —— 自动态下它是解析出的当前页；若处于固定态，✓ 移到被固定的那页。永远恰好一个。

目标态 · 多窗口（窗口号 = 行内右缀）· dark

标签页 · 4

节标只有一层「标签页 · N」，窗口信息下沉到行内小徽标；首个窗口（通常是当前窗口）不打标 —— 少即是多。
